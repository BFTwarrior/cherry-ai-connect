四、产品功能上传口径
======================================================================

源码中已包含以下 0.4.3 产品要求：
- 多中转站线路管理和 /v1/models 同步。
- 一个客户端 Key 只能绑定一条中转站线路。
- 客户端 Key 支持创建、编辑、复制、测试、启用、停用和永久删除。
- 思考强度统一为 low、medium、high、xhigh、max 五档。
- Responses 和 Chat Completions 请求会按客户端 Key 的等级写入对应字段。
- 中英文界面切换。
- 开机启动、启动后隐藏、关闭窗口进入托盘。
- 应用图标、窗口图标和托盘图标使用同一套 Cherry 紫色视觉资源。
- 重置网关会停止旧监听器，在 27891-27991 中随机选择新的可用端口并重新启动。
- 重置网关会保留线路、模型、客户端 Key、绑定关系和思考强度；旧本地 API 地址会失效。
- 客户端 Key 卡片可以快速复制本地 Key 和当前 API 地址。
- 上游 Key 只返回脱敏状态，真实值不返回到界面列表。
- 二次确认使用应用内紫色主题窗口，不使用系统原生确认框。

状态标签必须保持区分：
- 待修复：仍发现代码、构建或可重复回归问题。
- 待验收：开发侧已完成，等待测试人员按步骤现场确认。
- 待用户验收：需要用户本人确认视觉、托盘、Cherry Studio 实际对话或最终体验。

不能因为源码已上传，就把“待验收”或“待用户验收”改写成“已验收”。

五、公开仓库创建和上传顺序
======================================================================

第一阶段：创建仓库
1. GitHub 登录后选择 New repository。
2. Repository name 使用 cherry-gateway-desktop，或由维护者改成最终名称。
3. Description 可使用：Local multi-route gateway desktop app for Cherry Studio and OpenAI-compatible clients.
4. 选择 Public。
5. 不要勾选自动生成 README、.gitignore 或 License，因为本地项目已经准备好这些文件。
6. 创建后只核对仓库地址和账户名称，不在页面填写任何上游 API Key。

第二阶段：本地提交
1. 初始化本地 Git 仓库并保留当前 main 分支。
2. 提交前执行 git status --short 和 git diff --stat。
3. 只提交源码、文档、图标、package-lock.json、README.md、LICENSE 和配置文件。
4. 再做一次密钥扫描；扫描结果必须没有真实凭证。
5. 提交说明建议使用：feat: prepare Cherry Gateway 0.4.3 public release

第三阶段：上传和复核
1. 设置 GitHub 远程地址并推送 main。
2. 打开 GitHub 仓库首页，检查文件树、README、LICENSE 和产品文档是否可读。
3. 点击仓库的 Code 页面确认没有 node_modules、dist、gateway-data、.gateway-secret 或完整 Key。
4. 先把源码仓库作为 0.4.3 源码基线；安装包是否作为 Release 附件发布，另行决定。
5. 若发布安装包，Release 文案必须说明未进行 Windows 数字签名，用户首次运行可能看到系统安全提示。

1. 阅读 00-交付总览与文档索引.txt，确认状态标签和安全边界。
2. 阅读 测试人员完整说明.txt，按“环境检查 → 启动 → 线路 → 模型 → 客户端 Key → 思考强度 → Cherry Studio → 语言和托盘 → 重置网关”的顺序执行。
3. 使用临时中转站 Key 和临时客户端 Key；不要把完整凭证写回 GitHub Issue、测试文档或截图。
4. 重置网关时记录旧端口、新端口、旧地址失效、新地址健康和业务数据保留。
5. 测试完成后删除临时线路和临时 Key，并确认正式数据没有被误删。
6. 将结果写入测试记录和问题清单，严格区分待验收与待用户验收。
