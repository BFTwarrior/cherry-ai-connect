# 开发维护规则

## 代码分层

| 区域 | 责任 |
|---|---|
| `electron/` | 窗口、托盘、安装路径、生命周期和 IPC |
| `gateway/` | 本地 OpenAI 兼容 API、鉴权、转发和端口 |
| `renderer/` | React + TypeScript 页面、组件、主题和双语界面 |
| `sync/` | 加密数据、压缩、GitHub Release 同步和冲突处理 |
| `tests/` | 自动回归、故障注入和视觉预览 |

代码按职责拆分。单个模块内部按“类型、常量、状态、业务逻辑、视图、导出”分区，避免把逻辑全部堆在页面文件中，也不要为拆分而复制逻辑。

## 注释要求

核心代码使用清楚的中英双语注释。注释必须说明：负责什么、为什么这样处理、安全边界是什么、失败后如何处理。加密/解密、同步冲突、客户端 Key、端口重置、数据清理和版本迁移必须重点注释；显而易见的语句不逐行翻译。

## 产品不变量

- 一个客户端 Key 只能绑定一条线路，不能反推出上游 Key。
- 用户自定义 Key 名称后，线路改名不得覆盖。
- 同一设备更新、重启、同步不得刷新客户端 API Key。
- 永久累计 Token 不得因 50 MiB 请求明细清理而减少。
- 同步失败不得用空数据覆盖有效本地数据。
- 删除、停用、重置和冲突处理必须二次确认。
- 主色为深灰、紫色、金色；绿/红只用于状态或危险提示。

## 数据与发布

- 运行数据放在安装目录旁的 `data/`。
- GitHub 只使用用户自己的私有仓库，上传前加密并压缩。
- 不上传访问令牌、密码、明文 Key、完整本地路径、真实日志或未脱敏截图。
- 发布前核对界面版本、README、安装包名称、Release 标签、下载链接、SHA-256、凭据扫描和截图脱敏。
- 未经过对应测试的功能只能写“待验收”。
