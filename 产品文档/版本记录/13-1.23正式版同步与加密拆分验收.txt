# Cherry AI Connect 1.23 正式版：同步与加密拆分验收

## 目标

- 以 1.23.0 代码为正式版基线，生成 Windows x64 NSIS 安装包。
- 同步编排、同步协议、GitHub Release 访问、本地保险库和加解密保持独立职责。
- 保险库的 Argon2id、AES-256-GCM、AAD、DEK 包裹、压缩和 envelope 校验只由 `sync/sync-crypto.mjs` 负责。
- 保持旧 `sync/vault.mjs` 导入路径兼容，不改变现有 vault 数据格式和 schema 1 协议。

## 模块边界

| 模块 | 正式职责 |
| --- | --- |
| `sync/sync-manager.mjs` | 桌面生命周期、凭据状态、调度和 UI 状态发布 |
| `sync/sync-engine.mjs` | manifest-last 提交顺序、父代检查、资产回读校验、合并和垃圾回收 |
| `sync/github-provider.mjs` | 私有仓库、固定 Release 和不可变资产的 GitHub 请求 |
| `sync/local-vault-store.mjs` | 本地文件、原子写入、备份、系统保护的 DEK 和远端 envelope 导入 |
| `sync/sync-crypto.mjs` | 保险库加密/解密、Argon2id、AES-256-GCM、AAD、DEK wrapper 和格式校验 |
| `sync/vault.mjs` | 仅作旧路径兼容的显式 re-export |
| `sync/sync-common.mjs` | 不含秘密的稳定序列化、压缩、哈希、资产描述和 manifest 校验 |

## 同步专项自动化证据

- manifest 必须最后上传；中断候选不会清空 outbox。
- 本地 vault 不可用时仍可同步用量，并继承上一份远端加密配置。
- 用量-only 同步不会覆盖远端有效的加密配置。
- 双设备合并不会重复累计 lifetime totals。
- 全新设备会先采用远端数据集，再验证并解密远端 vault。
- 错误密码和篡改数据不会写入本地，也不会替换现有配置。
- 不同设备的同计数配置编辑会进入显式冲突处理。
- GitHub token 错误信息会脱敏；公开仓库会被拒绝；不可变资产不会重复上传。
