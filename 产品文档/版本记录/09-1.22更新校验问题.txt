# 1.22 更新校验问题

更新时间：2026-09-18（UTC+8）　状态：已发布

## 问题

设置页能显示最新版本，但安装包显示“—”，并提示“安装包缺少可验证哈希值”，下载按钮被禁用。截图中的同步状态是成功的，因此这不是云端数据丢失问题。

## 已确认原因

1. 更新器优先请求 GitHub Releases API。
2. 当前网络对匿名 API 触发了 GitHub 限流，实际返回 `API rate limit exceeded`。
3. 旧逻辑在 API 失败后只读取 `releases/latest` 的跳转地址，只能得到版本号，不能得到安装包 URL 和 SHA-256。
4. GitHub Release 页面仍有安装包和 SHA-256，所以会出现“版本已发现、安装包不可用”的间歇性状态；限流恢复后又可能正常。

## 1.22 修复范围

- API 限流或不可用时，读取官方 Release 页面及资产片段。
- 从官方页面提取安装包地址和 SHA-256；继续要求 SHA-256 校验通过后才能安装。
- API、页面或资产信息不完整时仍然禁止安装，不以“看起来像官方文件”代替哈希验证。
- 增加解析测试，覆盖“API 没有 digest、Release 正文和资产页面有 SHA-256”的实际情况。
- 1.22 不改变同步数据、客户端 API Key、更新备份和安装覆盖规则。

## 当前不处理、留到 1.23

- GitHub 同步偶发 `GitHub request timed out`、稍后自动恢复的问题：记录为网络/API 超时专项，不在 1.22 顺手修改。
- 测试 1.22 期间发现的其他问题：只记录版本、复现步骤、证据和影响，不临时插入修复。

## 验收标准

- API 正常时能显示版本、安装包和校验值。
- API 被限流时仍能从官方 Release 页面取得安装包 URL 与 SHA-256。
- 缺少或格式错误的 SHA-256 时，下载/安装继续禁用。
- 下载后计算出的文件哈希与发布值不一致时，删除临时安装包并停止更新。
- 同一设备更新后，`data/`、客户端 API Key 和同步配置保持不变。
