# 测试与验收

## 自动与视觉检查

1. `npm run check`
2. `npm test`
3. `npm run renderer:build`
4. `npm run dist`
5. 启动打包程序，确认本地服务和 `/health` 版本。
6. 使用预览脚本检查默认窗口、English、统计记录、悬浮引导、设置页和更新卡片。

预览数据是假数据，不能代替真实环境验收。

## 测试数字口径

- v1.36 的测试数字只属于历史公开版本记录，不代表当前 Latest。
- 公开 v1.37 发布基线为 47/47；对应公开安装包和哈希仍按 v1.37 发布记录核对。
- 2026-09-25 当前工作树为未发布 v1.37.1 候选，最新实测为 75/75；该数字不回填公开 Release，版本元数据只在候选构建中更新。
- 报告测试数量时必须同时写明版本、工作树/发布范围和日期；自动化通过不等于真实设备、客户端或云同步已验收。

## 真实环境必测

| 范围 | 必测内容 |
|---|---|
| GitHub | 首次同步、线路检测后的自动同步、30 分钟同步、换 Token、断网、冲突、新设备恢复 |
| 客户端 Key | 同设备覆盖更新/重启/同步后不变；新设备首次恢复生成本机新 Key |
| 更新 | 下载、SHA-256、备份、覆盖安装、中断恢复和数据完整性 |
| Windows | 安装、卸载、托盘、自启、启动隐藏、关闭同步和真正退出 |
| 线路/统计 | 真实线路、模型、流式首字、Token、缓存、50 MiB 清理 |
| Codex 官方统计 | 本机 loopback 可用/不可用、独立来源、未知指标、不与中转站重复计数；账户级用量仍以 Codex `/usage` 为准 |
| 1.23 | 首次同步后自动显示全部旧线路，不得要求先创建新线路 |

记录只写版本、UTC+8 时间、步骤、结果和脱敏截图。不要删除 `data/` 或重新生成客户端 Key 来掩盖问题。
