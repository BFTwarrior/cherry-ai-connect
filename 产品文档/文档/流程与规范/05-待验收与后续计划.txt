## 官方 Codex 统计与使用统计页改造总计划（历史计划，原文保留）

本节保留原始范围和执行顺序，避免丢失决策背景；已完成与未完成事项以当前实现记录为准。

### 1. 功能开关与数据边界

- 正版 Codex 官方 token 统计默认开启，产品中不提供开启/关闭开关，行为固定写入实现。
- 官方 Codex 统计与中转站统计必须是两套独立数据源、独立统计口径、独立缓存和独立云同步资产；不得把官方 Codex 数据伪装成某条中转站线路。
- 为官方 Codex 记录预留独立 50 MB 空间；容量不足时只能裁剪官方 Codex 的明细记录并保留其汇总，不能覆盖中转站记录或共同占用中转站的历史配额。
- 用户通过 Codex 接入本地 API 或中转站时，必须先制定来源归因和去重规则；在没有稳定请求标识前，不能把官方记录和本地网关记录直接相加。

### 2. 使用统计页的独立视觉体系

- 使用统计页的设计、特效、层级和状态反馈单独维护，不直接套用其他页面的普通卡片动效；后续实现时必须逐项核对统计页专属底色、图表、筛选器、历史记录区、分页区和缓存提示区。
- 统计页的装饰动效不能遮挡图表、筛选菜单、历史记录文字、数值或分页按钮；动效必须服从数据可读性、对齐和性能降级规则。
- 统计页需要明确记录默认态、悬停态、聚焦态、展开态、选中态、禁用态、加载态、空数据态、错误态和缓存裁剪提示态；每种状态的中英文文字与视觉反馈保持一致。

### 3. 历史记录筛选框

- 在历史请求记录区域增加清晰的统计来源筛选，至少包含三项：
  - 全部 / All：显示官方 Codex 与中转站的合并视图，但必须保留来源标识，不能隐藏数据来源。
  - Codex 官方 / Codex Official：只显示正版 Codex 官方统计。
  - 中转站 / Relay Stations：只显示本地中转站和各条中转线路统计。
- 筛选框需要重新排版，核对左右间距、上下基线、菜单宽度、选中态、箭头位置和展开方向；不能挤压“单行/双行”、缓存容量、分页和历史记录标题。
- 三项筛选在中文和英文下都要保持同等层级、同等语义长度和稳定对齐；英文较长时应通过合理宽度和换行策略解决，不得缩小到影响可读性。
- 全部视图中的每条记录必须有明确来源字段或视觉标记，避免用户误以为所有 token 都来自中转站。

### 4. “全部线路”筛选

- 图二所示“全部线路”筛选菜单中增加正版 Codex 的专用名称；官方 Codex 必须和普通中转线路使用不同的数据来源标识，但保持同一套菜单结构、选中符号、边框、间距和动效。
- 中文显示使用“Codex 官方”或最终确认的官方中文名称；英文显示使用“Codex Official”或最终确认的英文名称；不得只增加中文而遗漏英文分支。
- “全部线路”仍表示全部来源，不得因为增加官方 Codex 项而改变原有中转线路筛选逻辑。

### 5. 中英文界面与文字规范

- 所有新增标题、筛选项、来源标识、缓存说明、空状态、错误提示、分页提示、容量提示和云同步字段都必须同时提供中文和英文。
- 英文版不能直接拼接中文名称；产品名、来源名、统计类型和字段名需要建立固定映射表，避免同一个概念在不同页面出现多个译名。
- 新增文字需要重新检查按钮宽度、筛选框宽度、表格列宽、图表图例、空状态和弹出菜单，不允许中文正常而英文挤压、截断或改变布局平衡。

### 6. 云同步与数据命名

- 官方 Codex 统计使用独立、明确的云同步名称，例如 `codex-official-usage`；最终字段名必须与本地数据表、缓存文件、云端资产名和恢复逻辑一致。
- 云同步状态、冲突提示、备份和恢复必须能区分官方 Codex 统计与中转站统计；不得复用原中转站 usage ledger 的模糊名称。
- 同步失败、冲突、恢复和旧版本兼容都要分别记录官方 Codex 统计的状态，不能因为中转站同步成功就默认官方统计也成功。

### 7. 英文根目录与 GitHub 命名

- 当前用户指出根目录仍使用“AI网关”等中文命名；后续整理时，GitHub 仓库、项目根目录、发布文档标题、构建产物说明和主要目录名统一改为英文。
- 英文命名需要先建立唯一命名表，优先使用产品名 `Cherry AI Connect` 或最终确认的英文项目名；不能一部分使用 `AI Gateway`，另一部分使用 `Cherry Connect`，造成仓库、文档和安装包名称不一致。
- 中文可以保留在中文说明、用户提示和本地化文档中，但不能继续作为 GitHub 面向用户的主目录名或正式项目标识。
- 本次只登记命名整理要求，不立即重命名当前根目录，避免破坏脚本路径、构建路径、历史文档链接和 Git 状态。

口径补充：OpenAI 官方文档把 Codex `/usage` 定义为账户令牌活动入口，把 `/status` 定义为当前会话、上下文和限额摘要。本产品这里的“Codex 官方”只是来源标签；当前实现只读本机 `127.0.0.1:43189` loopback API，不登录账户、不读取认证文件，也不声称替代账户级官方总量。参考：https://learn.chatgpt.com/docs/developer-commands 、https://learn.chatgpt.com/docs/app-server

### 已完成

- 新增 `gateway/codex-usage-client.mjs`：固定读取本机 `codex-usage` loopback API，默认地址为 `http://127.0.0.1:43189`；不读取 `auth.json`、会话 JSONL、聊天正文或密钥，也不写入中转站 usage ledger。
- 官方统计固定开启，不提供用户开关；服务不可用时返回明确的 unavailable 状态，不把不可用误报为零用量或关闭来源。
- 使用统计页增加 `全部 / All`、`Codex 官方 / Codex Official`、`中转站 / Relay Stations` 三项来源标签；切换来源时累计量、趋势、记录总数和记录明细同步切换，官方会话以 session 聚合记录显示。
- 中转站和官方 Codex 在响应模型中使用独立来源标识；中转站继续使用账本明细配额，官方 Codex 使用独立的内存明细缓存（45 MB 裁剪目标、50 MB 硬上限），全部视图仅在读取层合并，不自动把两类记录写入同一来源。
- 没有稳定的跨来源 request ID 时不自动去重，避免把 Codex 通过本地 API 使用的记录错误删除；当前仍需后续补充可验证的归因规则。
- 合并视图分页改为先分别取得两类来源的前段记录，再按时间统一排序后分页；超过单次安全读取上限的极深页仍需真实数据量现场验证。
- 官方 Codex 会话接口没有提供 HTTP 状态、首字时间、总耗时和流式标记时，界面显示“未知”，不再伪造 200、0ms 或“非流式”。
- 已补充中英文标签、来源名称、官方服务状态、缓存容量说明和响应表格的排版；现有浏览器演示页已核对全部、官方、中转三种状态。
