Cherry AI Connect V1.40 最终版本交付与交叉验证记录
更新时间：2026-09-25
状态：代码修改完成，自动化回归通过，V1.40.0 安装包已构建并通过尺寸门禁；未发布 GitHub Release。

一、版本目标
1. 版本识别统一为 V1.40；内部 npm/Electron 版本为 1.40.0，网关和界面显示为 1.40。
2. 修复更新过程中先同步、切换到同步页或其他页面后更新状态丢失的问题。
3. 更新期间阻止同步连接、冲突解决和网关重置绕过暂停闸门，避免并发读写本地数据。
4. 修复 Cherry Studio 检测并启用阶段的线路状态误判：模型目录失败不再无条件显示“线路可用”，已有缓存模型且目录接口不支持或被限流时才保留“可尝试调用”的明确状态。
5. 修复上游 URL 或 API Key 变化后仍暴露旧模型目录的问题；过滤空模型和非法模型项，并保留网络错误码供诊断。
6. 统一用量统计的成功口径：只有 HTTP 2xx 算成功，3xx 重定向与 4xx/5xx 都计入错误；官方 Codex 与中转站账本仍保持分离。
7. 安装包继续输出到 dist/current-build，历史 dist 根目录资产不作为本版本候选产物；最终安装包必须小于 100MB。

二、已修改的功能区域
1. 更新与页面恢复
  1.1 主进程在等待更新前同步之前先写入 syncing 快照。
  1.2 页面重挂载优先使用 active 和带序号的进度快照。
  1.3 窗口销毁或切页期间 IPC 广播失败不会破坏主进程状态。
  1.4 更新失败仍恢复旧网关，安装器未启动时不覆盖当前版本。
2. 同步安全闸门
  2.1 普通同步、定时同步和更新前同步共享同一管理器轮次。
  2.2 connect 和 resolveConflict 不再直接调用绕过协调槽位的 engine.sync。
  2.3 更新暂停期间拒绝新的连接和冲突解决请求。
  2.4 更新期间拒绝 reset-gateway，防止网关被并行停止或重启。
3. Cherry Studio 与线路诊断
  3.1 providerView 增加 routeVerified，区分“配置启用”和“已验证可用”。
  3.2 缓存模型存在且目录接口 unsupported/rate_limited 时，保留可尝试调用的线路状态。
  3.3 auth、timeout、network、5xx 或无缓存目录失败时显示线路未确认，不再过度承诺可用。
  3.4 URL 或上游 Key 变化会清空旧模型缓存和旧检测时间。
  3.5 上游网络错误码保留；非法模型对象不会变成字符串 undefined。
4. 用量账本
  4.1 append、远程合并、聚合、筛选和错误计数全部采用 2xx 成功边界。
  4.2 3xx 重定向回归测试加入本地账本测试。
  4.3 官方 Codex 独立来源和 50MB 本地明细缓存边界保持不变。

三、交叉验证分层
1. 重点项目：每个项目由 3 个独立只读代理复核，主代理再整合。
  1.1 更新状态与更新前同步：复核快照、页面切换、取消、失败恢复、闸门和 IPC。
  1.2 Cherry Studio 与模型目录：复核深链、/v1/models、缓存目录、错误分类和检测并启用语义。
  1.3 同步与统计：复核并发串行化、更新暂停、冲突路径、2xx 统计、官方/中转站隔离和数据保留。
2. 非重点项目：至少 2 次验证。
  2.1 构建与文档由独立代理复核版本号、产物目录、命名、文档一致性和 100MB 约束。
  2.2 主代理再执行 npm test、TypeScript 检查、渲染构建、差异空白检查和最终安装包检查。
3. 代理边界：本轮 10 个代理全部只读，不修改工作区，不创建子代理；所有修改由主代理统一整合。
