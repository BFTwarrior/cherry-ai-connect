# Cherry AI Connect 严重问题核查文档

更新时间：2026-09-25（UTC+8）

## 文档用途

本文件用于记录会造成数据丢失、同步失效、错误发布或安全边界破坏的严重问题。
后续每次版本开发、更新、同步、加密解密拆分、安装包构建和 GitHub 发布前，必须优先核查本文件；未完成核查或没有证据的项目只能标记为“待确认”。

## P0：本地数据不得丢失或被旧数据覆盖

- 更新、重启、卸载重装和异常恢复不得删除、清空或回滚 `data/`。
- `usage.db`、路由配置、客户端 Key、加密保险库和同步状态必须分别核对更新前后是否保留。
- 更新恢复指针必须绑定目标版本，并且只能一次性消费；已消费、旧版本或未来版本指针不得再次恢复。
- 发现空目录、部分目录、版本不匹配或恢复异常时，必须保护性停止，不能用空数据继续启动。
- 旧备份只能保留和待人工核对，不得静默覆盖当前数据。
- 验收必须包含：旧版本到当前版本覆盖更新、连续重启、更新失败后再次启动、数据目录权限异常和恢复中断。

## P0：同步必须可验证、可恢复、不可静默丢失

- 同步模块必须单独拆分，不能把同步失败隐藏在界面成功状态中。
- 必须分别核查 GitHub 凭据、匿名用量数据、加密保险库和同步 manifest；任何一项失败都要有明确状态和错误原因。
- 加密保险库故障不得阻塞用量同步，也不得覆盖或删除上一份有效的云端敏感配置。
- 同步失败必须记录错误类型、失败时间、下次重试时间和最终恢复结果。
- 必须覆盖首次同步、再次同步、断网恢复、GitHub 超时、fetch 失败、冲突、旧数据恢复和新设备恢复。
- 同步完成后必须核对本地数据、云端 manifest、版本号、数据序列号和恢复结果，不能只看按钮提示。
- 任何同步重试必须幂等，不得重复生成、覆盖或上传错误版本的数据。
- 未填写上游 API Key 不得阻塞本地模式、界面使用、配置保存或安全更新；只有实际调用上游线路时才报告线路 Key 缺失。

## P0：加密与解密边界

- 加密模块和解密模块必须独立于同步模块，明确输入、输出、版本、密钥来源和失败行为。
- GitHub 不得保存明文客户端 Key、密码、访问令牌或未加密保险库。
- 解密失败、密钥不匹配、数据损坏和版本不兼容时，必须保留原始有效数据并给出可定位错误。
- 任何加密格式变更必须提供版本标记、兼容策略和回滚验证，禁止无版本覆盖旧密文。
- 发布前检查安装包、Web Demo、日志、临时目录和上传资产，不得包含密钥、令牌或真实敏感数据。

## P0：版本与 GitHub 发布一致性

- `package.json`、锁文件、网关健康检查、渲染器显示、安装包文件名、`latest.yml`、tag 和 Release 正文必须使用同一版本。
- Release 只允许上传唯一正确的安装包、blockmap、Web Demo 和 `latest.yml`，不得混入旧包、临时包或敏感截图。
- 发布前必须核对工作树干净、测试结果、安装包大小、SHA-256、SHA-512 和平台架构。
- 发布后必须逐项核对 GitHub Release 的公开状态、Latest、tag、正文、下载链接、文件大小和远端哈希。
- 必须验证缺哈希、哈希错误、安装包下载失败和 GitHub 网络超时时的安全行为。
- 发布后必须复核启动、覆盖更新、数据目录、客户端 Key、同步、重启和托盘行为。
