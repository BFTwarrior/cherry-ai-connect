# v1.40.2 关键问题修复记录

更新时间：2026-09-25（UTC+8）

## 范围

本版本处理四个用户明确指出的问题：软件版本显示不一致、Cherry Studio 检测并启用“众智 AI”线路失败、Codex 官方使用日志读取失败，以及使用统计中 Codex 官方线路必须固定置顶。GitHub 主页的改动仅限仓库根目录 `README.md`，没有新增或修改软件主页入口。

### 本次追加要求

#### 使用统计线路下拉顺序

- `All routes / 全部线路` 仍是选择器的第一项。
- `Codex Official / Codex 官方` 固定为第二项，不参与中转站名称排序，也不因轮询刷新改变位置。
- 其余中转站线路继续按名称排序；来源标签、providerId 筛选和统计合并规则不变。

## 1. 版本显示问题

### 代码边界

#### 需要保持一致的版本来源

- 根因：`package.json` 和安装包版本已经是 `1.40.1`，但 renderer 和 gateway 仍各自硬编码 `1.40`。
- 修复：统一发布版本为 `1.40.2`，同步 `package.json`、`package-lock.json`、renderer 页脚/设置页和 gateway 管理接口版本。
- 验证：`tests/prepare-dist.test.mjs` 强制检查 package 与 lock 版本一致，避免再次出现“当前版本低于最新版本”的显示漂移。

## 2. Cherry Studio 检测并启用

### 运行路径

#### 模型目录兼容分支

- 根因：部分上游线路能正常转发聊天请求，但 `/v1/models` 返回 404、限流或空/无效目录；网关把空目录原样返回，Cherry Studio 因此把线路误判为不可用。
- 修复：仅对已经完成检测且明确属于 `unsupported`、`rate_limited` 或 `invalid-response` 的目录兼容问题提供 `default` 兼容占位模型；鉴权失败、网络失败、超时和普通错误不会被伪装成成功。
- 边界：占位模型只用于客户端发现流程，实际聊天仍使用客户端提交的真实 `model`，不会强制把 `default` 发送给上游。
- 验证：provider-health 自动化测试覆盖无缓存模型目录、Cherry Studio `/v1/models` 响应和真实聊天转发。

## 3. Codex 官方统计

### 桌面生命周期

#### 启动、读取和退出

- 根因：网关读取 `127.0.0.1:43189` 的方式和解析器是可用的，但桌面主进程没有启动 `codex-usage` 本地服务，所以页面显示“官方统计读取失败”。
- 修复：Windows 安装包内置 XZ 压缩的 `codex-usage-windows-amd64.exe`；首次启动解压到独立运行数据目录，再只在 43189 未被占用时运行 `serve`，已有用户服务不会被接管；退出时只停止当前程序自己启动的进程。
- 隔离：官方统计继续使用独立来源和独立 50 MB 上限，不写入 relay ledger，也不读取认证文件、聊天正文或密钥。
- 验证：保留真实 API 的嵌套 `usage` 字段解析测试，并增加辅助程序路径解析测试；发布前必须检查 43189 的 `/api/v1/summary`、`/timeseries`、`/sessions` 返回有效数据。
