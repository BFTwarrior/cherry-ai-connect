Cherry 多线路网关桌面版
版本：0.4.3

一、产品定位
这是一个运行在 Windows 本机上的 API 网关桌面控制台。它在 Cherry Studio、其他 OpenAI 兼容客户端和真实中转站之间增加一层本地管理壳，用本地客户端 Key 代替直接暴露上游 Key。

二、核心目标
1. 一条中转站线路保存一个上游 API URL 和一个上游 API Key。
2. 一个客户端 Key 必须绑定且只能绑定一条中转站线路，形成“一个上游 Key 对应一组本地客户端 Key”的清晰关系；客户端使用本地 Key，不接触真实上游 Key。
3. 支持配置多家中转站，并从每条线路的 /v1/models 获取模型列表，在界面按线路分组展示。
4. 思考强度 low、medium、high、xhigh、max 必须真正写入转发请求，而不是只修改界面文字。
5. 客户端 Key 支持创建、编辑、启用、停用和永久删除；线路删除前要检查绑定关系，避免误删正在使用的线路。
6. 支持简体中文和 English；支持开机自动启动、启动后隐藏到托盘、关闭窗口时隐藏到托盘。
7. 提供深灰色与紫色为主的桌面界面，信息分组明确，操作路径接近成熟的桌面配置工具。

三、使用边界
1. 本版本只监听本机 127.0.0.1；首次默认端口为 27891，启动或重置时可在 27891-27991 范围内选择可用端口，不直接对公网开放。
2. 不加入额外的“本地路由供应商”概念；本地网关只是客户端与中转站之间的管理层。
3. 上游请求是否成功仍取决于中转站地址、网络线路、上游 Key、模型权限和代理软件状态。

五、非目标与验收边界
1. 本版本不是公网 API 服务，不提供远程访问、账号体系或多用户权限管理。
2. 本版本不加入额外的“本地路由”概念；一个客户端 Key 的线路来源就是它自己的绑定关系。
3. 本版本不使用 SQLite，配置仍以本地 JSON 保存；是否迁移数据库属于后续独立版本，不影响 0.4.3 验收。
4. “待用户验收”代表需要用户本人观察托盘、Cherry Studio 完整对话或最终体验，不能由开发侧代码检查替代。

六、最终体验
用户只需要在 Cherry 中填写：
本地 API 地址：从设置页复制当前显示的 http://127.0.0.1:端口/v1；重置网关后端口可能变化
本地客户端 Key：由本软件生成的 cg_ 开头 Key
模型：从本软件同步出来的模型

真实的中转站 URL 和 API Key 只在本机网关配置中使用。

七、0.4.3 体验补充
1. 客户端 Key 卡片提供一键复制本地 Key 和本地 `/v1` API 地址，降低 Cherry 配置的操作成本。
2. 本地客户端 Key 与上游中转站 Key 明确分层：客户端只接触本地凭证，真实上游 Key 留在本机网关内。
3. 网关重置只随机本地端口，不改变 IP、线路或业务数据，用于快速处理本机端口冲突。
