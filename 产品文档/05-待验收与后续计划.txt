# 待验收与后续计划 / Pending acceptance and next plan

更新时间：2026-09-17（UTC+8）

## 当前待用户验收 / Pending user acceptance

1. 用真实私有 GitHub 仓库验证首次同步、恢复、换 Token、过期/撤销、断网和冲突。
2. 用真实中转线路和 Cherry Studio 验证模型、五档思考强度、流式首字、Token、缓存和错误码。
3. 在干净 Windows 环境验证安装、覆盖安装、卸载、托盘、自启、启动隐藏、关闭同步和真正退出。
4. 验证明细超过 50 MiB 后只清理旧详情，永久累计统计、线路和客户端 Key 不受影响。

## 后续版本记录方式 / Future issue format

新问题只登记一次，使用下面的最小字段；确认修复后再移动到对应版本的实现与发布文档：

`编号｜发现日期（UTC+8）｜版本｜问题｜验收标准｜状态`

状态只用：`待确认`、`待修复`、`待验收`、`已完成`。未明确批准的事项只记录，不修改当前版本。

## 维护提醒 / Maintenance reminders

- 发现界面问题时同时记录页面、窗口尺寸、语言、复现步骤和脱敏截图。
- 发现同步问题时保留本地 `data`，先记录错误码、同步编号和网络状态。
- 发布新版本时更新界面版本、README、安装包、Release、哈希和本目录文档；不要只改其中一处。
