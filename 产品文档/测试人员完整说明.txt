二、先记住的产品规则

1. 产品正式名称是“Cherry AI 连接中心”，英文为“Cherry AI Connect”；旧名称只在历史资料中出现。
2. 一个客户端 Key 必须且只能绑定一个中转站线路。客户端只使用本地 Key，真实上游 Key 只保存在本机网关内。
3. 思考强度为五档：low、medium、high、xhigh、max。网关会把等级写入转发请求，但上游是否接受由中转站和模型决定。
4. 网关只监听本机 127.0.0.1，不提供公网访问。端口在 20000-48999 中安全随机选择；重置会更换端口，但保留业务数据。
5. 使用明细缓存上限 50 MiB，超过后清理到约 45 MiB；界面“最近 200 条”只是分页显示。永久累计 Token 不受时间、清理、重启、重置或语言切换影响。
6. 运行数据在安装目录旁的 data 文件夹；不要手动删除、移动、重命名或覆盖其中的 config.json、usage.db、vault.enc、device.json、sync-state.json 和 backups。

三、严格测试顺序

1. 安装与启动：安装后启动，确认窗口标题、产品名称和版本为 1.00；确认左下角或状态区显示网关在线。
2. 设置：切换中文与 English，确认菜单、按钮、弹窗、空状态和统计页文字都随语言切换；检查开机自启、启动隐藏、关闭进托盘和检查更新。
3. 线路：添加一条测试中转站线路，保存后执行检测和同步模型；确认成功、失败、未检测三种状态不会混淆，模型按线路分组显示。
4. 模型：确认搜索、筛选、单线路同步和失败重试；不要把不同线路的模型堆成一个无归属列表。
5. 客户端 Key：新建 Key 时必须选择线路和思考强度；默认名称应跟随线路名。手动改名后，线路改名不得覆盖自定义名称。
6. 复制：在 Key 卡片使用“复制 Key”和“复制地址”；确认复制的是本地客户端 Key 和当前实时 /v1 地址，不是上游 Key。
7. Cherry Studio：填写当前地址、客户端 Key 和已同步模型，发送“你好”验证成功；网关日志和测试报告不得出现真实上游 Key。
8. 思考强度：分别创建或编辑 low、medium、high、xhigh、max 的测试 Key，确认界面保存值与请求转发字段一致；上游不支持时记录真实错误，不得把失败写成成功。
9. Key 生命周期：分别验证停用、启用、永久删除。删除必须二次确认；删除后认证立即失败，列表不再保留该 Key。请使用临时 Key，不要删除唯一正式 Key。
10. 使用统计：发送多次成功和失败请求，确认实时记录、24 小时/7 天/30 天/90 天/半年筛选、折线图、请求明细、Token、缓存命中率和永久累计均可读；重启后永久累计仍在。
11. 重置网关：记录旧端口，点击“重置网关”并确认；确认端口在 20000-48999 内且发生变化，旧地址失效，新地址健康，线路、模型、客户端 Key、绑定关系和思考强度均保留。
12. 托盘与退出：关闭窗口后确认进入托盘而不是停止网关；从托盘菜单执行真正退出，再重新启动确认数据仍在。若托盘图标进入隐藏区域，请检查 Windows 通知区域。
13. 卸载边界：只在测试完成后测试卸载；先备份 data，再确认程序卸载不会误删用户希望保留的记录。不要在测试过程中手动清空 data。

四、记录格式

每项记录：编号、日期（UTC+8）、测试包版本、操作步骤、预期结果、实际结果、状态、截图路径、备注。
状态只能使用：
- 待修复：开发侧仍可复现。
- 待验收：开发侧已修复并完成自动/接口回归，等待测试人员现场执行。
- 待用户验收：必须由用户本人确认视觉、托盘、Cherry Studio 实际对话或最终体验。
- 已验收待删除：只有明确验收后才可使用；不要擅自删除历史记录。

五、失败时的排查顺序

先确认网关在线，再检测线路，再同步模型，再确认客户端 Key 未停用且绑定正确，最后核对 Cherry Studio 的 /v1 地址、Key 和模型。重置网关后必须重新复制地址。网络代理只影响访问上游，不应影响本地界面。
