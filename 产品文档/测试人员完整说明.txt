======================================================================
一、这是什么软件
======================================================================

Cherry 多线路网关桌面版是一个运行在 Windows 本机上的 OpenAI 兼容 API 网关。

它位于 Cherry Studio 等客户端和真实中转站之间：

Cherry Studio  ->  本地网关  ->  已配置的中转站线路  ->  模型服务

使用本软件后，Cherry Studio 不需要直接保存真实中转站 API Key，只需要保存本软件生成的本地客户端 Key。
本地客户端 Key 与一条中转站线路绑定。网关验证客户端 Key 后，会在本机取出加密保存的上游 Key，向对应中转站转发请求。

本软件的核心目的：
1. 保护真实上游 API Key，不让 Cherry 或测试人员的客户端配置直接暴露上游 Key。
2. 统一管理多家中转站线路和它们支持的模型。
3. 为不同客户端 Key 单独绑定线路和思考强度。
4. 在本机提供一个稳定的 OpenAI 兼容地址，方便 Cherry Studio 使用。
5. 出现本地服务异常时，可以通过“重置网关”按钮随机更换本地端口，而不用手动打开命令行。

======================================================================
三、代码总体设计
======================================================================

1. 桌面层：Electron
Electron 负责创建窗口、加载 React 页面、处理系统托盘、设置开机启动、隐藏窗口和退出程序。
Renderer 页面不能直接访问 Node.js 文件系统；需要访问桌面能力时，React 通过 preload.js 暴露的安全接口调用主进程。

2. 界面层：React + TypeScript + Vite
React 将界面分成总览、线路、模型、客户端 Key 和设置五个主要视图。
TypeScript 用于约束 Provider、ClientKey、GatewaySettings 等数据结构，减少字段拼写和状态混乱。
Vite 负责把 renderer/src 编译成 renderer/dist，Electron 运行时加载编译后的静态文件。

3. 网关层：Node.js HTTP Server
gateway/gateway.mjs 使用 Node.js 原生 HTTP/HTTPS 模块，不依赖 WSL。
它默认监听本地 27891 端口；启动时如果端口被占用会在 27891-27991 范围内找可用端口，提供管理 API 和 OpenAI 兼容 API。

4. 配置层：本地 JSON
线路和客户端 Key 的管理配置保存到应用数据目录中的 config.json。
上游 API Key 不以明文保存，而是使用 AES-256-GCM 加密；客户端 Key 只保存 SHA-256 摘要，完整客户端 Key 只在创建成功时返回一次。

5. 线路关系
线路 Provider 保存：线路代号、名称、上游 URL、加密后的上游 Key、模型列表和检测状态。
客户端 Key 保存：名称、Key 摘要、绑定的 Provider、思考强度、创建时间和启用状态。

一个客户端 Key 必须绑定一条线路，不能创建没有线路的客户端 Key。
删除线路前，如果仍有客户端 Key 绑定，系统会拒绝删除并提示先改绑或删除客户端 Key。

6. 模型同步
点击同步时，网关使用上游 Key 请求该线路的 /v1/models。
成功后保存模型名称、同步时间、延迟和可用状态。
模型目录页面按线路分组展示，模型名称以卡片网格显示，不把所有模型堆到一个文本框中。

7. 请求转发
客户端使用本地客户端 Key 请求 /v1/responses 或 /v1/chat/completions。
网关先验证本地客户端 Key，再按照绑定线路选择上游 URL，并把认证头替换成真实上游 Bearer Key。
本地客户端 Key 不会转发给上游。

8. 思考强度
支持 low、medium、high、xhigh、max 五档，界面下拉框只显示这五项。
Responses 请求使用 reasoning.effort。
Chat Completions 请求使用 reasoning_effort。
因此思考强度不是只改界面标签，而是会写入真正转发的 JSON 请求。
上游是否接受某一档仍由中转站和模型能力决定；如果上游不支持 xhigh 或 max，测试人员应记录上游返回的错误。

======================================================================
四、启动后的正常状态
======================================================================

首次启动后，正常情况应满足：
1. 主窗口可以打开，标题为 Cherry Gateway。
2. 左下角显示“网关在线”和当前端口；首次正常启动通常为 27891。
3. 顶部显示绿色状态点和当前 127.0.0.1 端口。
4. 总览卡片可以显示中转站线路数、同步模型数、有效客户端 Key 数和默认思考强度。
5. 已配置线路显示名称、代号、URL、模型数、客户端 Key 数和最近检测结果。
6. 如果线路还未检测，显示“未检测”；检测成功后显示“可用”和耗时；失败后显示“异常”。
7. 系统托盘中应出现与 EXE/任务栏同图形的 Cherry 紫色图标。单击图标显示窗口，右键可以打开菜单。
8. 关闭主窗口默认只隐藏到托盘，不停止本地网关。
9. 通过托盘“退出”才会完全退出程序并释放当前监听端口。

======================================================================
五、每个界面和按钮的功能
======================================================================

【左侧导航】

1. 总览
显示当前网关摘要、四项统计、配置进度、默认线路和线路快照。
正常状态：能看到网关在线、至少一条线路、模型数量和有效客户端 Key 数。

2. 中转站线路
管理上游 URL 和上游 API Key。
正常状态：每条线路显示可用/异常/未检测状态、模型数、绑定 Key 数和检测时间。

3. 模型目录
按中转站分组查看模型，支持搜索、线路筛选和单线路同步。
正常状态：每条线路一个分组，模型以网格卡片显示。

4. 客户端 Key
创建和管理给 Cherry 使用的本地客户端 Key。
正常状态：列表只显示脱敏 Key，不显示真实完整 Key。

5. 设置
修改默认思考强度、现有 Key 批量应用、托盘行为、语言和本地连接设置。线路不在设置页重复选择，而是在创建/编辑客户端 Key 时绑定。

6. 打开数据目录
打开本机运行时数据目录，不修改配置。
测试人员打开后不要把 config.json 或 .gateway-secret 上传到公开位置。

【顶部工具栏】

1. 本地地址状态胶囊
显示本地网关地址和在线状态。它是状态展示，不是线路选择器。

2. 思考 HIGH 按钮
点击后进入设置页，显示当前默认思考强度。

3. 刷新按钮
这是“刷新并重置网关”按钮，不只是刷新页面。
点击后执行以下顺序：
- 关闭当前内嵌网关的 HTTP 监听。
- 清理已知旧版 Cherry 网关/旧本地代理的残留 Node 进程。
- 在 127.0.0.1 上选择一个新的可用随机端口（27891-27991）重新启动内嵌网关。
- 重新读取线路、模型、客户端 Key 和设置。
- 显示“网关已重置，已切换到随机端口”。
端口可能改变，所以 Cherry Studio 中的 API 地址需要从设置页重新复制；127.0.0.1 本身不变。
这个操作不会删除线路、模型目录、客户端 Key、Key 绑定关系或思考强度。
重置的目的，是在本机端口与其他应用网关冲突时快速换到可用端口，不是更换上游线路，也不是随机化公网地址。

4. EN/中按钮
切换简体中文和 English，同时更新界面和托盘菜单。

【总览页】

1. 添加中转站线路
打开添加线路窗口。填写线路代号、名称、API URL 和上游 Key。
保存后会自动检测 /v1/models。

2. 管理客户端 Key
直接跳转到客户端 Key 页面。

3. 四步配置中的“添加一条中转站线路”
跳转到线路页面或打开线路添加窗口。

4. “同步上游模型目录”
跳转/执行模型同步流程。成功后统计和线路状态刷新。

5. “生成一个客户端 Key”
跳转到客户端 Key 页面；如果没有线路，先要求添加线路。

6. “在 Cherry 中使用客户端 Key”
进入客户端 Key 页面，便于复制本地 Key 和查看配置提示。

7. 线路快照中的“管理线路”
跳转到中转站线路页面。

8. 线路快照中的“同步模型”
只同步对应线路，成功后显示模型数量和检测耗时。

9. 线路快照中的编辑按钮
修改线路名称、URL 或上游 Key。线路代号不可随意修改，因为它是内部绑定标识。

10. 线路快照中的删除按钮
永久删除线路。若仍有客户端 Key 绑定，操作会被拒绝并显示改绑提示。

【中转站线路页】

1. 添加线路
新建一条上游线路。线路代号只允许字母、数字、下划线和短横线。

2. 同步模型
请求上游 /v1/models。成功后保存模型目录、检测状态、时间和延迟。

3. 编辑线路
修改线路资料。上游 Key 留空表示保留旧 Key，不会因为编辑名称而清空密钥。

4. 删除线路
永久删除线路。绑定关系检查优先于删除。

5. “先检测，再绑定”说明
提醒测试人员：先确认线路可用，再创建客户端 Key；这样 Cherry 的测试不会因为上游线路本身不可用而误判。

【模型目录页】

1. 线路筛选
选择全部线路或某条线路。

2. 搜索模型名称
按模型 ID 模糊筛选，适合模型很多时查找。

3. 同步全部
依次检测所有线路，顶部显示本次成功数量。

4. 分组中的同步
只更新当前线路，不影响其他线路。

5. 模型卡片
展示模型 ID 和当前属于哪条线路。模型 ID 应与上游返回一致。

【客户端 Key 页】

1. 生成客户端 Key
打开创建窗口。必须填写名称、选择一条线路和思考强度。
生成成功后完整 Key 只展示一次，测试人员必须立即复制。

2. 编辑
修改名称、绑定线路和思考强度。修改不会重新生成旧 Key。

3. 停用
保留记录但立即禁止认证，适合暂时停止使用。

4. 启用
恢复已停用 Key 的认证。

5. 删除
永久删除本地客户端 Key。删除后 Cherry 使用旧 Key 应收到 invalid_gateway_key。
这是不可逆操作，测试时需要确认后再点击。

6. 创建结果窗口中的复制
把完整客户端 Key 写入剪贴板。

7. 创建结果窗口中的“我已保存，完成”
关闭完整 Key 窗口。关闭后列表只显示脱敏摘要。

【设置页】

1. 默认思考强度
设置新客户端 Key 的默认值，也可配合“同时应用到现有 Key”批量修改已有 Key。

2. 同时应用到现有 Key
勾选后保存设置，会把现有客户端 Key 都改成当前选择的等级。

3. 线路绑定规则
设置页不再提供“默认线路”选择，避免与“一客户端 Key 只绑定一条线路”的核心模型重复。新建或编辑 Key 时必须明确选择一条线路；旧配置中的 defaultProvider 仅作为兼容请求的内部回退，不是用户配置入口。

4. 开机自动启动
写入 Windows 登录启动项。登录 Windows 后自动运行网关。

5. 启动后隐藏到托盘
开机启动时不弹出主窗口，但网关继续运行。

6. 关闭窗口时隐藏到托盘
勾选时点击右上角关闭只隐藏窗口；取消勾选时关闭窗口会退出程序。

7. 简体中文 / English
切换界面、按钮、提示和托盘菜单语言。

8. 本地 API 地址复制
复制当前界面显示的实时 /v1 地址，粘贴到 Cherry Studio 的 API 地址字段；重置后必须重新复制。

9. 打开数据目录
打开运行时配置文件夹，用于备份和排查，不要公开分享密钥文件。

10. 顶部刷新按钮
如果网关出现异常，优先点击顶部刷新按钮完成网关重置，再重新测试 Cherry。

【系统托盘菜单】

1. 显示 Cherry 网关：恢复主窗口。
2. 隐藏到托盘：隐藏主窗口但继续运行。
3. 开机启动：切换 Windows 登录启动状态。
4. 退出：完全退出程序，释放本地端口。

======================================================================
六、在 Cherry Studio 中导入并测试
======================================================================

前置条件：
1. Cherry 多线路网关桌面版已经启动。
2. 总览页左下角显示“网关在线”。
3. 中转站线路页至少有一条线路，状态为“可用”。
4. 模型目录页可以看到该线路的模型。
5. 客户端 Key 页已经生成一个绑定该线路的本地客户端 Key。

Cherry Studio 配置步骤：

1. 打开 Cherry Studio。
2. 进入模型服务商/模型供应商设置。
3. 新增一个 OpenAI 兼容服务商，或者编辑一个用于测试的 OpenAI 兼容服务商。
4. API 地址填写：
设置页“本地 API 地址”当前显示的实时地址（通常形如 http://127.0.0.1:27891/v1）。重置后端口可能变为 27xxx，不能继续使用旧地址。
5. API Key 填写 Cherry 多线路网关生成的客户端 Key，不要填真实中转站 Key。
6. 模型名称填写模型目录中同步出来的模型 ID，例如测试人员实际看到的模型名称。
7. 保存服务商配置，刷新模型列表。
8. 新建对话，选择刚配置的模型。
9. 发送：
你好，你是什么模型？
10. 检查是否能正常返回回答。

推荐的完整测试顺序：
1. 先在网关里点击线路“同步模型”，确认状态为“可用”。
2. 在 Cherry 中填写本地 API 地址和客户端 Key。
3. 选择同步到的模型，发送简单问候。
4. 在网关设置中把客户端 Key 的思考强度改为 medium，测试一次。
5. 再改为 high，测试一次。
6. 如果中转站明确支持 max，再测试 max；不支持时不要把上游报错当成本地网关故障。
7. 在网关中停用客户端 Key，再从 Cherry 发送请求，预期认证失败。
8. 重新启用客户端 Key，再发送请求，预期恢复。
9. 重新点击网关顶部刷新按钮，等待网关在线后再次发送请求。
10. 最后退出 Cherry 和网关，再重新打开，确认数据和线路仍然存在。

测试人员注意：
- Cherry 连接的是本地地址，不是上游地址。
- Cherry 中不要填写或截图真实上游 API Key。
- 如果模型列表为空，先回到网关线路页同步模型，不要直接修改 Cherry 的模型名称。
- 如果本地地址打不开，先看网关是否在线，再点一次顶部刷新。

======================================================================
七、建议测试用例和预期结果
======================================================================

用例 01：启动
操作：双击安装后的 Cherry 多线路网关。
预期：窗口打开，左下角网关在线，首次通常使用 27891；若被占用则使用 27891-27991 内其他可用端口，托盘出现 Cherry 图标。

用例 02：健康检查
操作：根据界面当前端口，在浏览器打开 http://127.0.0.1:当前端口/health。
预期：返回 JSON，ok 为 true，version 为 0.4.1；端口与界面一致。

用例 03：检测线路
操作：线路页点击同步模型。
预期：显示可用、耗时和模型数量；模型目录出现分组。

八、常见问题排查
======================================================================

1. 页面打不开
先确认 Cherry 多线路网关进程正在运行；再看界面当前端口是否被其他程序占用；点击顶部刷新，让程序自动选择 27891-27991 内新的可用端口。

2. 网关在线但线路异常
本地网关正常，只代表本机服务正常。请检查上游 URL、上游 Key、Clash/VPN 和中转站额度。

3. 模型目录为空
进入中转站线路页，点击同步模型；检测失败时先修复线路，不要在 Cherry 中手填不存在的模型 ID。

4. Cherry 提示 Key 无效
确认填的是本软件生成的 cg_ 开头客户端 Key；确认该 Key 没有停用或删除；确认 API 地址包含 /v1。

5. 思考等级仍显示 medium
先确认客户端 Key 的思考强度，不只看全局默认值；再确认中转站是否在自己的记录中显示了对应字段；上游有权拒绝不支持的档位。

6. 托盘没有看到图标
先点击任务栏右侧的隐藏图标箭头，在 Windows 的“任务栏设置/系统托盘图标”中允许 Cherry Gateway 显示；确认程序没有被完全退出。如果仍然没有，重启应用并检查版本是否为 0.4.1；若仍看不到，检查 Windows 是否把图标折叠进通知区域溢出菜单。

7. 重置后地址是否变化
会变化端口，不变化 IP。重置会关闭旧监听器，并在 27891-27991 中随机选择新的可用端口；目的就是避开和其他应用网关的端口冲突。Cherry 需要重新填写设置页复制的新 /v1 地址。

8. 重置会不会删除配置
不会。重置不删除 config.json，不删除模型目录，不删除客户端 Key，不改变绑定关系。

9. 数据迁移
旧版桌面外的源码目录已经不再作为运行依赖。当前运行数据保存在 AppData\Roaming\cherry-gateway-desktop\gateway-data 中。

【A. 产品逻辑的两处澄清】

1. 为什么截图里像有两个“客户端 Key”
旧版页面同时在顶部标题和内容区重复显示“客户端 Key”，容易被误认为有两组 Key。0.4.1 已改为：顶部只保留一次页面主标题，内容区从 LOCAL ACCESS TOKENS 说明开始；列表中的真实记录数量以“本地访问凭证 N”为准。当前已有 1 条记录时，只能看到 1 张客户端 Key 卡片。

2. 为什么设置页不再有“默认线路”
一个客户端 Key 创建时必须绑定且只能绑定一条线路。把线路再做成全局设置，会让用户不知道请求到底按哪个线路转发，因此 0.4.1 已移除设置页中的默认线路选择。设置页只负责全局思考强度、批量应用、桌面行为、语言和连接信息；线路选择只出现在客户端 Key 的创建/编辑窗口。旧配置里的 defaultProvider 仅为兼容旧请求保留，不能作为新的用户操作入口。

3. 客户端 Key 的正确关系
中转站线路保存真实上游 URL 和真实上游 Key；客户端 Key 是给 Cherry 使用的外壳。一条客户端 Key 只指向一条线路。创建时没有线路不能提交；编辑时也不能保存空线路；删除 Key 后卡片消失，旧 Key 认证必须失效；停用只改变启用状态，记录仍保留。

- 未完成：蓝紫色 layers 图标；有线路但 modelCount 为 0 时仍未完成。
- 已完成条件：所有或至少当前配置线路存在成功同步的模型数量 totalModels > 0。

- 未完成：紫色/中性 shield 或 key 图标；只有生成 Key 还不等于已在 Cherry 使用。

【E. 状态变化验收矩阵】

1. 网关在线：绿色状态点、顶部地址胶囊、左下角端口和总览 Hero 端口必须相同；重启中使用琥珀色状态并显示“网关重启中”。
2. 网关异常：状态不能继续伪装为绿色；应显示错误 Toast/错误页，并允许点击重置。
3. 重置成功：Toast 显示新随机端口；顶部、左下角、总览、设置页和 Key 创建结果页全部更新。
4. 线路成功：绿色“可用”；线路失败：红色“异常”；未检测：中性色“未检测”。
5. Key 有效：绿色点和“有效”；停用：弱化卡片和“已停用”；删除：卡片从列表移除且旧凭证失效。
6. 思考强度：只允许 low、medium、high、xhigh、max 五项；界面标签必须与发送到网关的字段一致。
7. 语言切换：页面标题、按钮、说明、Toast 和托盘菜单不能只翻译一部分；数据、数量、绑定关系不能改变。
8. 端口改变：127.0.0.1 不改变；旧端口不再由本应用监听；业务数据和上游线路不改变。

【F. 重置网关的准确产品定义】

1. “重置网关”不是随机公网 IP，也不是随机中转站，更不是清空配置。
2. 它执行 stop -> 选择随机可用本地端口 -> start -> 重新读取业务数据。
3. 首次默认优先使用 27891；重置在 27891-27991 范围内排除旧端口，随机尝试可用端口。
4. 设计目的：当 27891 或当前端口被其他应用网关、代理工具、开发服务占用或残留进程阻塞时，让用户点击一次就快速换端口，不需要打开命令行排查。
5. 必须保留：线路列表、加密上游 Key、同步模型、客户端 Key 摘要、Key 启用状态、绑定线路、Key 思考强度、全局默认思考强度。
6. 必须改变：当前监听端口、实时 API 地址、界面中所有端口展示、给 Cherry 的复制提示。
7. 用户影响：Cherry 原来填写的旧 /v1 地址可能失效，必须从设置页复制新地址；客户端 Key 不需要重新生成，线路 Key 不需要重新填写。

十二、严格测试顺序与验收门槛
======================================================================

测试原则：每一步都先记录现象，再进行下一步；失败时不要直接删除 config.json 或密钥文件。测试人员可以使用自己的测试线路和一次性测试 Key，不能把真实上游 Key 写进报告。

第 0 步：版本和环境
1. 记录 EXE 版本、Windows 版本、是否经过 Clash/VPN、测试日期。
2. 确认使用 Windows x64；Node.js 只在开发/打包时需要，普通测试人员不需要安装 WSL。
3. 确认当前没有启动旧版 Cherry 网关目录中的 Node 进程。
通过标准：EXE 能启动，版本为 0.4.1，窗口标题为 Cherry Gateway。

第 1 步：启动与端口
1. 启动 EXE，记录顶部端口 P0；首次通常为 27891，若占用则记录实际端口。
2. 检查左下角端口、顶部端口、总览 Hero PORT 三处是否相同。
3. 浏览器访问 http://127.0.0.1:P0/health，将 P0 替换为实际数字。
4. 记录 JSON 中 ok=true、version=0.4.1、forcedLevel 和 providers 数量。
通过标准：本地健康检查成功，界面端口与健康检查端口一致。

第 2 步：视觉基线
1. 依次打开总览、线路、模型、客户端 Key、设置，不关闭程序。
2. 每页检查顶部是否只有一个页面主标题；特别核对客户端 Key 和设置不再出现重复大标题。
3. 检查右侧没有突兀的竖向滚动条，但鼠标滚轮仍可以滚动长页面。
4. 检查图标不是方块/缺失；主按钮为紫色，在线/成功为绿色，删除/异常为红色，模型为蓝色，思考为琥珀色。
通过标准：布局清晰、标题不重复、图标一致、页面可滚动、没有文字挤压或模型堆叠。

第 3 步：线路检测
1. 使用测试人员自己的中转站 URL 和 Key 添加一条线路。
2. 点击保存并同步，等待状态落定。
3. 记录线路代号、状态、耗时、模型数，不记录上游 Key。
4. 进入模型目录，核对模型按线路分组且数量一致。
5. 用错误 URL 或临时断开代理做一次失败测试；恢复网络后再次同步。
通过标准：成功显示绿色可用和模型数量，失败显示红色异常；失败不删除旧配置，恢复网络可重新同步。

第 4 步：五档思考强度
1. 在设置页确认下拉列表完整出现 LOW、MEDIUM、HIGH、XHIGH、MAX 五项，没有缺项或拼写错误。
2. 以每个等级分别创建/编辑测试 Key，或使用“同时应用到现有 Key”逐档测试。
3. 检查客户端 Key 卡片和顶部思考标签与所选等级一致。
4. 发送 Responses 和 Chat Completions 测试请求时，检查中转站记录/调试日志中的 reasoning.effort 或 reasoning_effort。
5. 最后恢复产品默认 HIGH，避免把测试设置留成 MAX。
通过标准：五档都能保存；字段真实进入转发请求。上游拒绝不支持的档位时，应记录为上游能力限制，不得误报为本地 UI 失败。

第 5 步：客户端 Key 生命周期
1. 创建一个临时 Key，确认必须选线路；逐一确认五档都能选。
2. 创建成功后立即复制完整 Key；关闭弹窗后回到列表，确认只显示脱敏摘要。
3. 编辑名称、线路和思考强度，确认旧 Key 值不变且卡片更新。
4. 停用 Key，使用它请求 /v1/models 或聊天，预期 invalid_gateway_key/401；再启用，预期恢复。
5. 如需测试删除，使用专门临时 Key；点击删除前记录卡片，确认后删除，列表数量减少且旧 Key 不能再认证。
6. 不要用唯一生产 Key 做删除测试；不要把完整 Key 截图或写入报告。
通过标准：客户端 Key 只有一条绑定线路；编辑、启用、停用、删除都能影响真实认证，不只是改文字。

第 6 步：Cherry Studio 导入
1. 从网关设置页复制当前实时 /v1 地址。
2. Cherry 新建 OpenAI 兼容服务商；API 地址粘贴本地 /v1；API Key 粘贴客户端 Key；模型填写同步到的模型 ID。
3. 先刷新模型，再发送“你好，你是什么模型？”。
4. 记录模型列表是否出现、聊天是否成功、响应耗时和请求类型。
5. 不要在 Cherry 中填写真实中转站 Key；不要把 API Key 发进测试群。
通过标准：Cherry 只连接 127.0.0.1 本地网关，模型和聊天可用；上游 Key 仍只在网关本机。

第 7 步：设置、语言和托盘
1. 切换 English，检查五个页面、按钮、说明和 Toast；再切回简体中文。
2. 打开/关闭“开机自动启动”“启动后隐藏到托盘”“关闭窗口时隐藏到托盘”，每次保存后重新进入设置核对。
3. 关闭窗口，观察是否进入托盘；单击托盘图标恢复；右键检查显示、隐藏、开机启动、退出菜单。
4. 只在最后一次测试使用托盘“退出”，确认 HTTP 端口释放；重新启动后数据应仍在。
通过标准：语言不影响数据；关闭窗口不停止网关；托盘图标可见且与 EXE 图标同源；退出才真正结束进程。

第 8 步：核心“重置并随机端口”测试
1. 在重置前记录：P0、设置页 API 地址、线路数量、模型数量、客户端 Key 数、Key 绑定线路、当前 HIGH 等级。
2. 确认 Cherry 当前可以读取模型或发送一次简单消息。
3. 点击顶部“重置网关”按钮一次，不要连续点击；先确认弹窗中写明旧 API 地址会失效、端口会随机变化、线路/模型/Key 会保留，再等待 Toast 和状态恢复。
4. 记录新端口 P1，并确认 P1 在 27891-27991 范围内；在一次正常测试中 P1 应与 P0 不同。
5. 确认顶部胶囊、左下角、总览 Hero、设置 API 地址、Key 创建结果提示都显示 P1。
6. 浏览器访问 http://127.0.0.1:P1/health，确认 ok=true；访问旧的 P0，确认旧端口不再由本应用提供健康响应（若被别的软件占用，记录占用者，不要停止它）。
7. 再读取线路、模型、Key 和设置，逐项与重置前记录比较。
8. 回到 Cherry，把旧地址改成新的 P1/v1，使用原客户端 Key 再测一次。
通过标准：只改变本地端口，不改变 IP、线路、模型、Key、绑定、思考强度；旧地址可能失效，新地址健康；Toast 明确说明随机端口；Cherry 更新地址后恢复。

第 9 步：重复重置和冲突恢复
1. 连续分两次点击重置，每次等待完成并记录端口。
2. 确认端口会从范围内重新选择，不能出现空端口、负数或固定写死旧值。
3. 如果能安全制造端口占用，只占用测试范围内的一个端口，不要停止不相关软件；启动/重置应跳过该端口。
4. 结束后释放测试占用端口。
通过标准：网关每次只存在一个本地监听器；重置不会因旧监听器或 Keep-Alive 连接未关闭而报端口占用。

第 10 步：打包回归
开发者执行：
1. npm run check
2. npm run renderer:build
3. node --check electron/main.js
4. node --check electron/preload.js
5. node --check gateway/gateway.mjs
6. npm run dist
通过标准：全部命令成功；EXE 位于 dist\Cherry-多线路网关-0.4.2.exe；安装包启动后仍能完成第 1-8 步；未签名 EXE 可能显示 Windows“未知发布者”，不等于功能失败。

======================================================================
十一、0.4.2 当前界面与验收补充
======================================================================

本节优先级高于文档中保留的 0.4.1 历史描述。测试人员应使用 0.4.2 安装包，并以界面实时显示的端口为准。

【A. 顶部区域】

1. 本地 API 地址
- 正常状态：左侧绿色状态点、地址显示为 `127.0.0.1:端口`。
- 点击地址：应复制完整的本地 API 根地址；成功显示复制 Toast，失败应出现可手动选择文本的提示。
- Cherry 使用地址：把地址末尾补成 `/v1`；不要把 `/health` 或 `/admin` 填入 Cherry。

2. 思考强度
- 顶部显示的是“默认思考强度”，不是强制覆盖已有客户端 Key 的全局开关。
- 五个可选值必须完整出现：`low`、`medium`、`high`、`xhigh`、`max`。
- 修改默认值后，总览、设置页和顶部控件应同步；已有 Key 的卡片等级只有在明确执行“应用到已有 Key”后才改变。

3. “重置网关”
- 这是高影响操作，不是普通页面刷新。
- 点击前必须出现影响说明：旧本地 API 地址会失效；新端口会在可用范围内随机选择；线路、模型、客户端 Key、绑定关系和思考等级保留。
- 点击确认后，顶部和左下角应进入“网关重启中”；重启完成并成功读取管理数据后才恢复在线。
- 完成后应显示新端口，并能复制新地址。旧端口由本应用释放；如果旧端口被其他软件占用，不得停止其他软件。

【B. 总览页】

1. 统计卡只读，不应点击后偷偷跳转或触发重复动作。
2. QUICK START 每行只对应一个动作：
- 没有线路：打开“添加线路”。
- 有线路但没有模型：直接执行同步。
- 有模型但没有客户端 Key：打开创建 Key。
- 有启用 Key 但没有真实请求：直接执行 Key 连接测试。
- 已完成：显示当前绑定线路和等级摘要，不再显示无法设置的“默认中转站”。
3. 第四步只有真实客户端请求成功后才算完成；仅有 Key、仅有模型或仅有线路都不能把它标为完成。

【C. 线路与模型页】

1. 线路卡片必须显示线路名称、状态、模型数量、绑定 Key 数量和最近同步时间。
2. 异常线路必须有红色状态和可读原因；常见原因包括连接拒绝、超时、域名错误、401/403。
3. 模型页按线路分组显示模型卡片，不允许把所有线路模型堆成一张无分组长列表。
4. 执行“同步全部”时必须显示当前序号/总数、正在处理的线路名和进度条。
5. 部分失败时保留成功结果，并显示失败线路和“重试失败线路”；不应强制用户重新等待已经成功的线路。

【D. 客户端 Key 页】

1. 产品规则是一条客户端 Key 绑定一条中转站线路。创建/编辑时线路为必选项，不能拆成独立的“客户端 Key”和“默认上游 Key”。
2. 正常卡片显示：脱敏 Key、绑定线路、思考等级、创建时间和启用状态。
3. “测试连接”只测试当前 Key 绑定的线路，成功显示模型数量；失败显示状态码或可读原因。
4. “停用”是可恢复的临时禁用；停用后使用该 Key 请求 `/v1/models` 或聊天应返回 401，再启用后恢复。
5. “删除”是永久删除本地凭证和卡片，必须确认；删除后旧 Key 不得继续认证。测试删除必须使用临时 Key，不得删除唯一生产 Key。
6. 复制完整 Key 仅在创建结果中提供一次；列表页永远只显示脱敏值，报告和截图不得出现完整 Key。

【E. 设置页】

1. 默认思考强度、开机启动、启动后隐藏、关闭窗口进托盘、语言切换均为即时保存；不应再寻找统一的“保存全部设置”按钮。
2. “应用到已有 Key”是独立动作，点击前必须看清影响范围；它不会改变线路绑定，也不会创建新 Key。
3. API 地址区域应显示当前实时端口，并提供复制入口和打开数据目录入口；侧栏不再提供第二个重复的数据目录入口。
4. 中英文切换后，页面标题、按钮、说明、状态和 Toast 都应切换；数据、Key 和线路不应改变。

【F. 托盘与图标】

1. EXE、窗口/任务栏和托盘应使用同一套紫色产品图形，不应出现 Electron 默认图标或空白图标。
2. 关闭窗口进托盘开启时，关闭窗口不应结束网关；从托盘单击应恢复窗口，右键菜单应包含显示/隐藏、开机启动和退出。
3. 如果图标未出现在任务栏通知区域，先检查 Windows 是否把它折叠到隐藏图标区域；不得直接判定安装包图标资源缺失。
4. 只有托盘“退出”才应结束桌面进程并释放端口。

【G. 清单状态填写规则】

- `待修复`：代码或可重复回归仍存在问题。本轮 0.4.3 不应再有该状态。
- `待验收`：开发者已修复，并已完成代码、构建或接口回归；等待测试人员执行开发验收步骤。
- `待用户验收`：需要用户本人实际确认的视觉、托盘、Cherry Studio 或使用体验项目；本轮明确不代替用户确认。
- `已验收待删除`：只有测试人员确认并留下证据后才能使用；当前不要擅自删除条目。

【H. 推荐测试顺序】

先执行构建/启动和健康检查，再做线路与模型，再做 Key 生命周期，再做五档思考等级，再导入 Cherry，再做语言/托盘，最后做重置网关和重复重置。任何一步失败，先记录版本、端口、线路代号、状态码和截图，再继续独立测试，不要用删除配置掩盖问题。

======================================================================
十二、0.4.3 客户端 Key 快速复制与上游密钥保密专项
======================================================================

本节是开发验收的执行稿。顺序不能随意打乱：先确认构建和网关健康，再使用临时 Key 做复制和删除，最后做重置网关。文档中的“待验收”是开发验收状态，不等于“待用户验收”；已有“待用户验收”的托盘、真实 Cherry Studio 对话和最终体验项目仍按原标签保留。

【一、版本与准备】

1. 使用 `dist\\Cherry-多线路网关-0.4.3.exe` 或解包目录中的 0.4.3 程序，不要用旧版 0.4.1/0.4.2 判断本节结果。
2. 确认程序左下角显示 0.4.3，顶部有本地地址、默认思考强度、重置网关和语言按钮。
3. 测试人员不得把真实上游 Key 粘贴进报告、截图、屏幕录制或聊天；需要记录时只写线路名称、端口、模型数量和状态码。
4. 本节删除测试 Key 是允许的，但不能删除唯一的正式 `Cherry 客户端`；正式 Key 若来自旧版本，不要为了测试“重新生成”而轮换它。

【二、构建检查】

按顺序执行：
1. `npm run check`：应通过，无 TypeScript 错误。
2. `npm run renderer:build`：应通过并生成前端产物。
3. `node --check gateway/gateway.mjs`：应通过。

【三、客户端 Key 卡片视觉检查】

进入“客户端 Key”页面，找到一张有效 Key 卡片。

1. 卡片背景为深灰/近黑色，边框为低对比度紫灰色；有效状态右侧使用绿色圆点和“有效”，停用状态使用灰色/弱化样式。

【四、复制 Key 测试】

1. 先通过“生成客户端 Key”创建一个临时 Key，名称建议使用 `__tester-copy__`，绑定已有可用线路，选择 HIGH。不要把生成出的完整值写入测试报告。

十六、0.4.3 交付版测试摘要与文档优先级
======================================================================

本节是交付给测试人员时的最后摘要。若本文件前面的历史章节与本节有文字差异，以本节和《00-交付总览与文档索引.txt》为准；前文保留用于追溯不同版本的测试背景。

【一、交付对象】

1. 版本：0.4.3，Windows x64。
2. 安装包：`C:\Users\BFTwarrior\Desktop\codex\Cherry多线路网关桌面版\dist\Cherry-多线路网关-0.4.3.exe`。
3. 源码根目录：`C:\Users\BFTwarrior\Desktop\codex\Cherry多线路网关桌面版`。
4. 实际运行数据通过“设置 > 打开数据目录”进入；不要把源码目录、安装目录或 `gateway` 源码目录当作运行数据目录。

【二、测试先后顺序】

1. 启动程序，记录版本、窗口尺寸、当前端口和网关在线状态。
2. 检查总览和健康状态；失败时先停止，不要继续修改正式线路。
3. 使用临时线路同步模型，检查模型按线路分组、成功状态、耗时和错误摘要。
4. 使用临时客户端 Key 测试创建、复制 Key、复制地址、测试连接、停用、启用和永久删除。
5. 逐项测试 low、medium、high、xhigh、max；不要只看下拉框，要检查请求或上游回显允许时的实际透传结果。
6. 在 Cherry Studio 中填入当前 `/v1` 地址、本地客户端 Key 和已同步模型，完成一次最短真实请求。
7. 检查中英文切换、窄窗口、二次确认、托盘、开机启动和关闭进托盘。
8. 最后执行重置网关；记录旧端口、新端口，确认旧地址失效、新地址健康、业务数据保留。
9. 清理临时线路和临时 Key，确认正式数据数量恢复，再提交测试报告。

【三、不得混用的状态标签】

1. `待修复`：仍有代码或可重复问题，需要开发继续修改；当前 UI-025 已不再属于此类。
2. `待验收`：开发侧已经做了代码、构建或接口回归，测试人员还需要按步骤执行开发验收。
3. `待用户验收`：需要用户本人确认托盘、Cherry Studio 完整对话、显示缩放或最终审美体验；本标签不能被测试人员因为“代码通过”而直接改成已验收。

【四、最终业务规则】

1. 一个客户端 Key 只能绑定一条线路；不能用设置页的“默认线路”替代绑定关系。
2. 中转站真实 Key 只存在于网关本机，客户端 Key 只是本地访问凭证。
3. 五档思考强度固定为 low、medium、high、xhigh、max；上游不支持某一档时，失败属于线路/模型能力边界，不代表本地下拉框失效。
4. 重置网关是随机更换 27891-27991 范围内的本地端口；它不是更换线路，也不是删除配置。
5. 旧版没有本机密文的 Key 不提供虚假的“复制 Key”；只能确认后重新生成，旧值立即失效。

【五、安全填写规则】

1. 报告只写线路代号、端口、HTTP 状态码、模型数量、延迟、错误摘要和时间。
2. 不要写入上游 API Key、完整客户端 Key、Authorization、config.json 内容或 `.gateway-secret`。
3. 截图前检查剪贴板、地址栏、创建结果窗口和终端输出；发现密钥先遮挡再保存截图。

【六、当前已知边界】

1. UI-025 低高度窗口下侧栏底部版本信息已完成开发修复，当前为待验收；请按第十七节现场确认。
2. 托盘是否被 Windows 通知区域折叠、关闭窗口后是否正确隐藏、单击恢复、Cherry Studio 完整聊天和最终视觉体验仍按待用户验收流程执行。
3. 0.4.3 使用本地 JSON 配置和 AES-256-GCM 加密，不需要 SQLite；不要自行替换运行时存储。

本节不记录任何真实 API Key。

======================================================================
十七、0.4.3 UI-025 修复后的最终开发验收
======================================================================

本节是最新开发修复的执行稿。它只处理 UI-025 低高度窗口侧栏裁切；“待用户验收”的托盘、Cherry Studio 完整对话和最终审美体验仍按前文原标签执行，不要混用状态。

【一、准备】

1. 使用最新 `dist\\Cherry-多线路网关-0.4.3.exe` 或 `dist\\win-unpacked\\Cherry 多线路网关.exe`，确认左下角版本为 0.4.3。
2. 先确认网关在线，再记录当前端口；不需要创建、删除或轮换正式客户端 Key。
3. 窗口先保持默认尺寸，再逐步缩小到程序允许的最低支持高度附近；若 Windows 显示缩放不是 100%，同时记录缩放比例。

【二、UI-025 检查】

1. 观察左侧栏完整高度：品牌区、工作台菜单、系统菜单、网关状态卡和底部版本行都应在窗口内。
2. 确认网关状态卡仍显示在线/重启中状态、当前端口、最近请求状态和“上游 Key 仅保存在本机”。
3. 确认状态卡下面完整显示 `Cherry Gateway` 和 `0.4.3`，文字不能贴边、被标题栏遮挡或只露出半行。
4. 切换到 English 后重复检查底部区域；英文状态文案可以换行，但不能覆盖版本号或把版本号挤出视口。
5. 进入线路、模型、客户端 Key 和设置页各一次，确认主内容仍可滚动，低高度适配没有把页面操作入口隐藏。

【三、回归边界】

1. 本次布局修复只涉及渲染层高度和总览装饰尺寸，不应改变线路、模型、Key、端口或设置数据。
2. 开发侧已通过 TypeScript、前端构建、Node 语法检查、Windows x64 打包和隔离接口回归；这不是桌面视觉现场通过的替代品。
3. UI-025 的开发验收填写“通过/不通过”并保留窗口尺寸截图；完成现场确认后，按项目规则再决定是否转为“待用户验收”，不要删除历史条目。

【四、当前标签】

1. UI-025：待验收，等待本节现场操作。
2. UI-001 至 UI-024：继续保持待用户验收；本轮不需要测试人员把它们改成已验收。
3. 托盘图标、关闭进托盘、单击恢复、开机启动、Cherry Studio 完整聊天和最终视觉审美：继续保持待用户验收。

本节不记录任何真实 API Key。
