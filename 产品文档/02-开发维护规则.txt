# 开发维护规则 / Development rules

## 代码分层 / Code structure

| 区域 / Area | 责任 / Responsibility |
|---|---|
| `electron/` | 窗口、托盘、安装路径、生命周期和 IPC |
| `gateway/` | 本地 OpenAI 兼容 API、鉴权、转发和端口 |
| `renderer/` | React + TypeScript 页面、组件、主题和双语界面 |
| `sync/` | 加密数据、压缩、GitHub Release 同步和冲突处理 |
| `tests/` | 自动回归、故障注入和浏览器视觉预览 |

代码按职责拆文件；单个模块内部按“类型、常量、状态、业务逻辑、视图、导出”分区。不要把所有功能堆在页面文件中，也不要为了拆分而复制同一套逻辑。

## 注释规则 / Comment rules

核心代码使用成对的中英注释。注释要说明：这段代码负责什么、为什么这样处理、不能违反的安全边界、失败时会发生什么。重要状态转换、加密/解密、同步冲突、端口重置和数据清理必须有注释；不用逐行翻译显而易见的代码。

## 不可改变的产品规则 / Product invariants

- 一个客户端 Key 只能绑定一条线路；客户端 Key 不能反推出上游 Key。
- Key 默认名称跟随线路；用户手动改名后设置自定义锁，不再自动覆盖。
- 思考强度固定为 `low / medium / high / xhigh / max` 五档。
- 本地端口只能从 `20000–48999` 中安全随机选择，并检查可绑定性；重置时必须结束旧监听并刷新入口。
- 永久累计 Token 单独保存，不能随 50 MiB 请求明细清理而减少。
- 删除、停用、重置和同步冲突必须二次确认；同步失败不得覆盖有效本地数据。

## 数据与安全 / Data and security

- 运行数据放在安装目录旁的 `data/`，不要默认写入用户目录或系统盘其他位置。
- 详细请求记录达到 50 MiB 后才清理最早明细；线路、客户端 Key、配置和永久累计不随之删除。
- GitHub 只使用用户自己的私有仓库；上传前加密并压缩，只上传必要的同步资产。
- 默认权限仅为指定仓库的 `Contents: Read and write` 与系统保留的 `Metadata: Read-only`。
- 不上传访问令牌、密码、明文 Key、个人完整路径、真实日志或未脱敏截图。
- 窗口图标、托盘图标和品牌图标使用同一套资源；主色为深灰、紫色、金色，绿/红只表达状态或危险。

## 发布约束 / Release checklist

发布前必须同步检查：界面版本、README、安装包名称、Release 标签、下载链接、SHA-256、文档状态、凭据扫描和截图脱敏。未经过对应测试的功能只能写“待验收”，不能写“已通过”。
