客户端 Key 快速复制、上游密钥保密与重置网关验收补充

适用版本：0.4.3 Windows x64

一、本次目标

1. 在客户端 Key 卡片的空白区域增加“复制 Key”和“复制地址”两个高频操作，减少用户在创建结果窗口、设置页和 Cherry 之间来回查找。
2. 客户端 Key 只是给 Cherry 使用的本地凭证；真实中转站 API Key 只留在网关本机并加密保存，不进入客户端 Key、模型列表、普通日志、Toast 或测试文档。
3. 保持“一条客户端 Key 只绑定一条中转站线路”的产品规则，不再把客户端 Key 和上游 Key 拆成两个需要用户理解的对象。
4. 保留“重置网关”的运维能力：随机更换本机端口，快速避开与其他本地应用的端口冲突，同时保留线路、模型和客户端 Key。

二、客户端 Key 卡片的界面约定

1. 卡片第一行从左到右：Key 图标、Key 名称、脱敏摘要；中间为快捷操作；右侧为“有效/已停用”状态。
2. “复制 Key”使用复制图标和紫色描边按钮。新版本创建的 Key 可以在卡片中再次复制，成功后显示“客户端 Key 已复制”。完整 Key 不在卡片文字中渲染，只在点击动作完成时从本机接口读取。
3. “复制地址”使用复制图标和紫色描边按钮，复制当前实时的本地 API 地址，格式为 `http://127.0.0.1:端口/v1`。成功后显示“本地 API 地址已复制”。重置网关后该按钮自动使用新端口。
4. 旧版本生成、但本地没有加密密文的 Key，会显示“重新生成”而不是假装可以恢复。点击后必须确认；确认后旧 Key 立即失效，生成新 Key，并打开一次性结果窗口。
5. 卡片底部继续保留“测试连接、编辑、停用/启用、删除”。“删除”是永久删除，必须使用测试 Key 验证，不得拿唯一的正式 Key 做删除测试。
6. 英文界面对应文字为 Copy key、Copy URL、Regenerate、Test connection、Edit、Disable/Enable、Delete；状态和 Toast 也必须同步切换。

三、保密边界与实际安全效果

1. 中转站 API URL 和上游 API Key 保存在网关数据目录，Key 使用本机网关密钥进行 AES-256-GCM 加密；前端列表只拿到名称、摘要、绑定线路、等级和 `hasSecret` 状态。
2. 客户端点击“复制 Key”时，桌面前端只向本机回环管理接口请求当前客户端 Key 的解密值；该接口不转发到任何中转站，也不把上游 Key 返回给客户端。
3. 网关默认只监听 `127.0.0.1`。因此，别人即使拿到本地生成的客户端 Key，也无法在另一台电脑上直接使用，因为另一台电脑访问不到这台电脑的 127.0.0.1 网关；客户端 Key 本身也不包含上游 API Key。
4. 这不是对“同一台电脑已被完全控制”的绝对防护。如果攻击者已经能在本机运行程序、读取剪贴板或访问网关，仍可能使用本地凭证。遇到这种情况，应立即停用、删除或重新生成客户端 Key，并更换中转站 Key。
5. 不要把上游 API Key、包含密文配置的数据目录或创建结果截图发到公开位置。测试记录只写端口、状态码、模型数、线路代号和脱敏摘要。

四、开发测试顺序

1. 先执行 `npm run check`、`npm run renderer:build`、`node --check gateway/gateway.mjs`，再执行 `npm run dist`。
2. 启动最终打包版，确认 `/health` 返回 `ok=true`、版本 `0.4.3`，再读取线路、模型和客户端 Key 统计。
3. 用临时线路/临时客户端 Key 测试完整生命周期：创建、复制 Key、复制地址、测试连接、停用、启用、删除。临时数据必须在测试结束前清理。
4. 用视觉界面确认卡片快捷按钮位置、颜色、禁用态、成功 Toast 和旧版 Key 的重新生成提示；不要只用接口结果代替界面验收。
5. 点击“重置网关”，确认影响提示后继续；记录旧端口、新端口、旧地址是否失效、新地址健康检查、线路/模型/Key 是否保留。
6. 最后重新读取客户端 Key 列表，确认只剩正式 Key；再核对安装包路径和文档路径。

十三、UI-025 低高度侧栏修复补充
======================================================================

更新时间：2026-09-11

1. 原因：渲染层 `.app-shell` 使用 680px 的强制最小高度，而 Electron 窗口在 Windows 标题栏和边框扣除后可能低于该值，导致页面底部超出视口，侧栏版本行被裁切。
2. 修复：改为 `min-height: 0`，侧栏设置 `min-height: 0` 和视口内布局，底部状态卡与版本行使用不可压缩的 flex 区域；这样低高度窗口不会再因渲染层额外撑高而隐藏底部信息。
3. 同步收紧总览欢迎区和右侧装饰尺寸，降低装饰对首屏工作信息的占用；不删除本地网关状态、端口和主要操作。
