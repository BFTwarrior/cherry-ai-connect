======================================================================
一、本版本功能结论
======================================================================

1. 客户端 Key 默认使用已绑定线路的显示名，用户未手动改名时持续跟随线路名。
2. 增加本地使用统计：实时请求记录、24 小时/7 天/30 天/90 天/半年图表、Token 和缓存统计。
3. 增加没有时间上限的“永久累计使用量”。详细记录到期清理后，累计值不得归零或减少。
4. 设置页增加手动检查更新，只读取 GitHub 最新 Release，不静默下载、不自动安装。

======================================================================
二、客户端 Key 名称跟随规则
======================================================================

1. 打开“客户端 Key > 生成客户端 Key”时，Key 名称应立即等于当前绑定线路名。
2. 切换线路且尚未手动改名时，Key 名应立即跟随新线路。
3. 创建后修改线路名称，自动命名的 Key 也应同步改名。
4. 用户输入与当前线路名不同的 Key 名称后，系统记录 nameCustomized=true。
5. nameCustomized=true 后，无论切换线路还是修改线路名，都不得再自动覆盖用户名称。
6. 弹窗必须显示“名称正跟随绑定线路”或“已使用自定义名称”。

======================================================================
三、使用数据和保留规则
======================================================================

可记录字段：
- 时间、本地客户端 Key 名、线路名、模型、接口、流式/非流式、思考强度。
- HTTP 状态、总耗时、首字时间 TTFT。
- 输入 Token、输出 Token、总 Token、缓存命中 Token、缓存创建 Token。

禁止记录字段：
- 用户提问、模型回答、系统提示词。
- 完整客户端 Key、上游 API Key、Authorization 请求头。

保留规则：
1. 可查询明细最多保留 180 天，同时最多 50,000 条，先到条件先执行。
2. 永久累计是独立总账，包含累计请求、失败、输入、输出、总 Token、缓存读写及首次/最近请求时间。
3. 详细记录超过半年被清理后，不得通过剩余明细重算永久总账。重启、网关重置、筛选和语言切换都不得影响总账。
4. 统计保存在实际运行数据目录的 usage.json。它含模型和时间等本地使用轨迹，不应提交到公开仓库。
5. 上游未返回 usage 时，仍记录请求、状态和耗时，Token 显示 0；程序不根据文字数伪造 Token。

======================================================================
四、使用统计页界面规则
======================================================================

1. 侧栏增加“使用统计 / Usage”，快捷键 Ctrl+5。
2. 顶部紫色大卡显示“永久累计使用量”，明确写出“没有时间限制”。
3. 24 小时、7 天、30 天、90 天、半年只影响当期卡片、图表和列表，不影响永久累计。
4. 支持线路、模型、全部/成功/失败筛选。统计“刷新”不得调用“重置网关”。
5. 摘要卡显示当期总 Token、输入、输出、缓存命中率和请求数。
6. 折线图使用深灰背景、紫色主线和可区分的输入/输出/缓存颜色，悬停显示精确值。
7. 请求表最新记录在上，2xx/3xx 绿色，失败红色，思考强度为紫色标签。
8. 切换中英文后，标题、筛选、图例、空状态、表头和保留说明都必须同步切换。

======================================================================
五、检查更新规则
======================================================================

1. 位置：设置页“检查更新 / Check for updates”卡片。
2. 点击“立即检查”后读取 BFTwarrior/cherry-gateway-desktop 最新 GitHub Release。
3. 有新版本时显示最新版本号和下载页面入口；无新版本时显示“已是最新版”。
4. 不传输本地配置、使用统计或密钥；不自动下载、替换 EXE 或安装。
5. 匿名 GitHub API 被限流时，程序使用官方 `releases/latest` 跳转地址读取标签；两条通道都失败才显示错误。

六、测试人员必须按此顺序验收
======================================================================

1. 记录版本 0.4.4、当前端口和网关在线状态。
2. 在设置页检查更新；记录当前版本、GitHub 返回版本和结果。断网时应显示可读错误，不应卡死。
3. 创建临时线路“统计验收线路 A”，打开生成 Key 弹窗，确认默认名称一致。
4. 将线路改名为“统计验收线路 B”，确认未自定义 Key 同步改名。
5. 手动把 Key 改为“Cherry 验收专用”，再改线路名，确认 Key 名不再变化。
6. 发请求前记录永久累计；分别发送一次非流式和流式请求。
7. 确认记录的状态、模型、线路、思考强度和 Token 与上游响应一致，永久累计增量等于两次 Token 之和。
8. 重启应用后再查看，永久累计不得丢失。
9. 切换五个时间范围和线路/模型/状态筛选，确认摘要、图表和列表变化，永久累计始终不变。
10. 切换 English 检查 Usage 和 Check for updates 排版，然后切回中文。
11. 重置网关，确认端口随机更换，但永久累计和明细不受影响。
12. 清理临时 Key 和临时线路，不得删除正式数据。
