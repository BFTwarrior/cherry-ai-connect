# Cherry AI Connect 1.21 问题与小调整

版本性质：小调整版　状态：已构建并发布，待真实环境验收　记录时间：2026-09-18（UTC+8）

## 问题：首次同步后线路列表为空

### 复现依据

视频：`\\192.168.1.101\Share4T\工作\bandicam 2026-09-18 01-12-47-858.mp4`

1. v1.1 中已有 5 条中转站线路。
2. 更新到 v1.2 后，在设置页连接 GitHub 并执行首次同步。
3. 同步结束后进入“中转站线路”，页面显示“还没有中转站线路”。
4. 不创建新线路时，已有线路不会显示。
5. 新增 1 条线路并提交后，原来的 5 条线路同时出现，列表变为 6 条。

### 判断

从现象看，云端或本地数据不一定丢失；更可能是首次同步完成后没有触发线路状态重新加载或页面刷新。新增线路触发了变更流程，意外地重新读取了完整线路数据。

影响：用户会误以为同步失败，可能重复添加已有线路；首次同步后的模型、客户端 Key 与线路绑定也可能暂时无法使用。

## 1.21 调整要求

- 首次同步成功后，自动恢复并显示全部已同步中转站线路。
- 不得要求用户先创建一条“占位线路”来触发刷新。
- 同步完成后主动刷新线路、模型和绑定关系；页面稍后打开时也要从已恢复数据初始化。
- 新增线路只能新增一条，不得因为刷新而重复保存旧线路。
- 同设备更新、重启和同步不得刷新客户端 API Key；新设备首次恢复规则保持不变。
- 同步失败或数据校验失败时保留有效本地数据，不得显示为空并覆盖本地配置。

### 删除四步引导模块

- 彻底删除首页及应用内的“四步完成配置”引导模块，包括悬浮窗、状态保存、完成后隐藏逻辑和相关文案。
- 删除后不得影响线路、模型、客户端 Key、统计、同步和更新功能。
- 更新或重启后不得重新出现该模块，也不能留下空白卡片、无效入口或未使用状态数据。

### 设置页面重新排版

- 当前界面语言卡片内容过少，右侧“安全与连接”卡片较高，导致两列高度不平衡并出现大面积空白。
- 重新组织设置页的卡片分组和宽度，让语言、桌面行为、请求策略、安全连接、云同步和更新区域形成清晰层级。
- 不要用强行拉高空卡片的方式填充空间；需要通过合理分组、横向布局或整行卡片解决留白。
- 中文和 English 状态下保持相同的视觉平衡；窗口缩小时要自然堆叠，不得产生溢出或难以阅读的长行。

## 验收标准

在已有 5 条线路的 v1.1 数据上覆盖更新到 1.21：

1. 连接同一 GitHub 私有仓库并完成首次同步。
2. 不点击“添加线路”，直接打开“中转站线路”。
3. 页面自动显示原有 5 条线路、模型数量、状态和绑定关系。
4. 重启软件后再次检查，结果不变。
5. 新增 1 条线路后只增加 1 条，不出现重复线路。
6. 同一设备的客户端 API Key 与更新前完全一致。
7. 首页和其他页面均找不到四步引导模块、入口或残留空白区域。
8. 删除引导后，线路、模型、客户端 Key、统计、同步和更新流程仍可正常使用。
9. 设置页左右区域高度和留白协调，界面语言卡片不再形成明显空缺。
10. 默认窗口、较窄窗口和 English 界面下，设置卡片均不溢出、不挤压、不出现异常空白。
