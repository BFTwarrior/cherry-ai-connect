======================================================================
一、这套浏览器验收到底是什么
======================================================================

我们把前端编译成静态页面，再在本机启动一个只监听 127.0.0.1 的临时预览服务，
用浏览器打开这个页面。为了让页面能够在没有 Electron 主进程的情况下运行，再向
页面注入一个“仅供预览”的 desktop 模拟接口。这个模拟接口会返回临时设置、同步
状态、冲突状态和更新检查结果。

它可以验收：
1. 页面是否能正常加载、排版是否完整、深灰紫色主题是否一致。
2. 中文/英文切换后标题、按钮、说明文字、导航和卡片是否同步切换。
3. 线路、模型、客户端 Key、思考强度、统计和设置模块是否显示正确。
4. 按钮点击后界面状态是否变化，确认窗口、错误提示、冲突面板是否正确。
5. 50 MiB 缓存说明、永久累计、趋势图、实时请求表是否容易理解。
6. GitHub 同步的连接中、冲突、恢复码、成功和错误状态是否按设计显示。
7. 页面截图能否作为测试人员的视觉证据保存。

它不能单独证明：
1. 最终 EXE 的 Electron 主进程、Node.js 子进程和 SQLite 原生运行是否正常。
2. Windows DPAPI/safeStorage 是否正常保护真实 Token。
3. 真实 GitHub 私有仓库是否能上传、下载、冲突和恢复。
4. 真实 Cherry Studio 请求是否真的到达上游中转站。
5. 系统托盘图标、开机自启、安装、覆盖安装和卸载是否正常。

因此浏览器验收属于“前端和交互预检”，必须和自动测试、打包版冒烟、真实 Cherry
Studio、真实 GitHub 及 Windows 安装验收分开记录。

三、从源码到浏览器页面的过程
======================================================================

步骤 1：构建前端
--------------------------------------------------------------------
在项目根目录执行：

    npm run renderer:build

Vite 会读取 renderer 目录，把 React/TypeScript 编译到 renderer/dist。这里不会
读取正式 EXE 的 data，也不会读取用户真实线路、Key、GitHub Token 或聊天内容。

步骤 2：启动视觉验收脚本
--------------------------------------------------------------------
在项目根目录执行：

    node tests/usage-preview.mjs

脚本会：
1. 创建操作系统临时目录 `cherry-usage-preview-*` 作为模拟数据目录。
2. 设置 `GATEWAY_DATA_DIR`，让临时网关只使用这个目录。
3. 启动一个假上游，返回可预测的输入 Token、输出 Token、缓存 Token 和少量 429
   错误，用来制造统计图和请求记录。
4. 启动临时本地连接服务。
5. 自动创建一条名为“Luna 高速线路”的假线路和一个临时客户端 Key。
6. 发送 36 次假的 Chat Completions 请求，生成统计和图表数据。
7. 启动 127.0.0.1:4173 静态预览服务。
8. 给 HTML 注入只在预览存在的 `window.desktop` 模拟接口。

步骤 3：用浏览器打开
--------------------------------------------------------------------
在浏览器中打开：

    http://127.0.0.1:4173

只保留一个当前预览标签页。页面打开后先观察整页，不要马上点击。先确认：
- 页面标题、左侧导航、顶部状态和内容卡片已经出现。
- 没有白屏、加载转圈不结束或控制台错误提示。
- 页面访问地址是 127.0.0.1:4173，而不是正式网关地址。

四、为什么每点一次都要重新读取页面
======================================================================

浏览器自动化不是“凭感觉点坐标”。每次页面状态改变后，按钮位置、可访问性编号、
截图编号和弹窗层级都可能变化，所以固定采用下面的循环：

    读取当前页面
        ↓
    观察文字、按钮、焦点和截图
        ↓
    只执行一个点击/滚动/输入动作
        ↓
    立即重新读取页面
        ↓
    核对预期结果

1. 需要文字和控件时，读取浏览器的可访问性树，使用当前观察中返回的按钮编号。
2. 需要判断颜色、间距、图标和遮罩时，读取当前截图。
3. 需要点击坐标时，必须使用本次截图返回的截图编号和坐标。
4. 页面切换、滚动、弹窗出现或语言变化后，旧编号和旧坐标全部作废。
5. 如果一次操作返回“结果未知”，不能盲目重试，必须先重新读取当前页面，确认
   实际状态后再做一次操作。

这样做是为了避免把一次失败误判为成功，也避免点击到已经变化的按钮。

五、实际使用的验收顺序
======================================================================

1. 总览页
--------------------------------------------------------------------
核对：
- `Cherry CONNECT` 品牌。
- “本地连接中心 / LOCAL CONNECTION CENTER”。
- 127.0.0.1 地址、端口、在线状态。
- 中转站线路、已同步模型、有效客户端 Key、默认思考强度四张统计卡。
- “四步完成配置 / Finish setup in four steps”。
- 当前 Key 路由和线路概览清晰分区。

2. 中文/英文
--------------------------------------------------------------------
点击右上角语言按钮，重新读取页面，核对：
- 中文切换到英文后，Overview、Routes、Models、Client keys、Usage、Settings 都出现。
- 顶部按钮、说明、统计卡、线路概览和底部状态卡同步变更。
- 英文不会出现旧的 `gateway` 普通用户文案；技术变量名不属于视觉问题。
- 再切回中文，确认状态没有丢失。

3. 设置页
--------------------------------------------------------------------
核对：
- Default reasoning level。
- Start with Windows、Start hidden in tray、Close to tray。
- 简体中文/English 两个语言按钮。
- Local API address 和 Copy。
- Reset connection service 的影响说明。
- data 路径说明，以及“删除软件目录会删除缓存、线路、客户端 Key、永久统计和
  未同步数据”的警告。
- GitHub cloud sync 的 30 分钟周期和重大事件同步说明。
- PAT 连接说明；页面不能写成 OAuth Device Flow 已完成。
- Check for updates 只检查、不自动下载、不自动安装。

4. GitHub 同步状态
--------------------------------------------------------------------
在预览页面通过 `window.__previewSetSyncConflict()` 注入冲突状态，核对：
- 页面出现冲突面板，而不是只出现通用红色错误。
- 本机和云端选择按钮有清晰含义。
- 恢复码输入内容被识别为恢复码，不会同时当作普通密码提交。
- 解决冲突后面板消失，状态恢复为可同步。
- 连接中、成功、待同步数量、下一次同步时间和错误状态排版完整。

5. 使用统计页
--------------------------------------------------------------------
核对：
- Lifetime usage / 永久累计使用量。
- 24 hours、7 days、30 days、90 days、6 months 五个范围。
- 输入、输出、缓存命中率、请求数统计卡。
- 颜色不同的趋势图线、图例和悬停说明。
- Live request log / 实时请求记录。
- `Latest 200 (one page)` 只表示单页展示量。
- `Local detail cache 0.0 / 50.0 MB` 明确表示容量上限，不是 200 条存储限制。
- 空数据时有清楚的空状态，不出现破碎表格。

6. 客户端 Key 和模型页
--------------------------------------------------------------------
核对：
- 客户端 Key 卡片可以显示绑定线路、思考强度、创建时间、状态和操作按钮。
- 快速复制 Key、复制地址、编辑、停用、删除按钮语义互不重复。
- 模型目录按照线路分组显示，不把所有模型堆成一个列表。
- 五档思考强度显示为 low、medium、high、xhigh、max。

7. 二次确认窗口
--------------------------------------------------------------------
打开重置、删除、停用或冲突解决操作的确认窗口，核对：
- 深色半透明遮罩。
- 深灰面板、紫色边框或主题色强调。
- 标题、影响说明、取消按钮和确认按钮与主界面字体、圆角和颜色一致。
- 重置使用琥珀色风险提示，删除使用红色风险提示。
- Esc/点击遮罩取消，Enter 确认（以实际页面支持情况为准）。

八、结束、清理和故障排查
======================================================================

正常结束：
1. 停止预览脚本（发送 Ctrl+C 给启动它的终端）。
2. 确认 4173、27890、27891 的预览进程已经退出。
3. 确认临时目录 `cherry-usage-preview-*` 已由脚本清理。
4. 不要删除用户正式安装目录的 data。

常见问题：
1. 浏览器打开空白：重新运行 `npm run renderer:build`，再启动预览脚本。
2. 页面有旧内容：确认使用的是 4173 预览地址，刷新后不要使用旧标签页的截图编号。
3. 点击后看起来没反应：重新读取页面；语言切换和异步数据加载可能需要短暂等待。
4. 找不到控件：先读取可访问性树，再使用当前返回的编号，不要沿用上一次编号。
5. 端口被占用：不要关闭用户的旧版连接服务；换用隔离的预览端口并在报告中记录。
6. 页面显示“Up to date”：这只是模拟检查结果；真实更新检查必须在最终 EXE 中另测。

九、和最终 EXE 验收的关系
======================================================================

推荐的完整验收链路：

浏览器预览 UI 验收
        ↓
TypeScript、语法和 20 项自动测试
        ↓
干净 dist 构建和 version=1.00 解包冒烟
        ↓
独立目录安装、托盘、开机自启、卸载
        ↓
真实 GitHub 私有仓库同步
        ↓
真实 Cherry Studio 请求和五档思考强度
        ↓
最终敏感信息扫描、哈希和发布验收

只有浏览器预览通过，不能直接推出“安装包通过”；只有本地模拟通过，不能推出
“真实 GitHub 同步通过”。每一层都要单独记录预期、实际、截图和测试时间。
