# Cherry AI Connect 使用说明 / User guide

适用版本：1.2　时间：2026-09-17（UTC+8）

## 这是什么 / What it does

Cherry AI Connect（Cherry AI 连接中心）在本机管理多条 AI 中转线路，再给 Cherry Studio 等客户端提供一个本地 API 地址和客户端 Key。上游 Key 只在本机使用，客户端不会直接看到它。

## 第一次使用 / First setup

1. 打开“中转站线路”，新增地址、上游 Key 和默认思考强度，先测试线路。
2. 打开“模型目录”，同步模型并确认线路分组正常。
3. 打开“客户端 Key”，生成一个 Key 并绑定一条线路。
4. 把软件显示的本地 API 地址、客户端 Key 和模型填入 Cherry Studio。
5. 发送一条测试请求，确认返回成功后再开始正常使用。

一个客户端 Key 只能绑定一条线路。Key 名称默认跟随线路名称；用户手动改名后，后续线路改名不会覆盖该自定义名称。

## 日常功能 / Daily use

- 线路：可新增、编辑、停用、删除、单条检测、全部检测和刷新模型。
- 模型：按线路分组显示，每组可独立折叠；搜索结果仍可见。
- 客户端 Key：可复制本地地址或 Key、编辑、停用和删除；危险操作会二次确认。
- 思考强度：`low`、`medium`、`high`、`xhigh`、`max` 五档；上游不支持时按错误提示处理。
- 使用统计：支持实时记录、24 小时、7 天、30 天、90 天、180 天和永久累计 Token；请求记录可切换“紧凑单行/详细双行”，明细清理不会减少永久累计值。
- 端口冲突：使用“重置连接服务”，软件会换端口、结束旧监听并刷新本地 API 地址。
- 更新：在设置页检查到新版本后，由用户点击“下载并更新”。软件会校验安装包、同步并备份数据，再启动覆盖安装；不会未经确认安装。

## GitHub 云同步 / GitHub cloud sync

同步使用用户自己的 GitHub 私有仓库。创建 Fine-grained personal access token 时：

| 项目 / Item | 应选择 / Select |
|---|---|
| Repository access | `Only select repositories` |
| Repository | 只选择专用私有同步仓库 |
| Repository permission | `Contents: Read and write` |
| 自动保留权限 | `Metadata: Read-only` |
| 不需要 | `All repositories`、`Actions`、`Administration`、`Secrets` 及其他无关权限 |

令牌创建后只显示一次，请立即复制到软件；不要发到聊天、Issue、截图或公开仓库。令牌过期或撤销时，在 GitHub 创建同样权限的新令牌，在软件中替换；新令牌同步成功后再撤销旧令牌。同一个同步仓库可以继续使用，不需要重建仓库。

同步规则：正常低频同步为每 30 分钟一次；开启、关闭、启动、退出、点击右上角关闭、线路新增/编辑/检测和刷新模型等事件会进入去重同步队列。设置页显示上次和下次同步时间，统一使用 UTC+8。同步失败时保留本地数据，不用空数据覆盖本地配置。

同一设备升级、重启或重新同步时，原客户端 API Key 必须保持不变。如果本地密钥异常缺失，软件会停止恢复并提示处理，不会静默生成新 Key。只有全新设备第一次从云端恢复时，才会在新设备本机生成新的客户端 Key；此时需要把新 Key 配置到 Cherry Studio。

## 重要安全提醒 / Safety

安装目录旁的 `data` 不是普通临时缓存，里面可能有线路配置、客户端 Key、永久统计和未同步记录。删除或移动前请先确认已经备份；不要用删除 `data` 的方式处理报错。

四步配置引导是应用内的可拖动悬浮窗。完成一次后会永久隐藏；升级、重启和同步不会让它重新出现。
