# Cherry AI Connect 关键经验

1. 数据必须放在安装目录旁的 `data`，不能默认写入 C 盘用户目录。
2. `data` 不是普通临时缓存，删除前必须提醒用户；它包含配置和统计。
3. 详细请求缓存按 50 MiB 清理，累计 Token 不能随缓存删除。
4. 重置网关不是简单刷新页面，必须停止旧监听、随机新端口并刷新所有 API 入口。
5. 端口冲突要在 `20000–48999` 内重新选择并再次检查可绑定性。
6. 客户端 Key 和线路 Key 必须保持一对一绑定，不能拆成让用户分别选择的两套配置。
7. 线路改名只同步到未被用户手动改名的客户端 Key。
8. 思考强度必须是五档；界面显示成功不等于上游真正支持，失败要明确提示。
9. GitHub Token 只授权指定私有仓库；`Contents: Read and write` 足够，`Metadata: Read-only` 保留默认项。
10. Token 过期、撤销、权限不足和仓库错误要分开提示；同步失败不能覆盖本地数据。
11. 浏览器预览不能证明托盘、安装器、真实线路和真实 GitHub 权限。
12. 发布前必须扫描明文凭据、脱敏截图、核对安装包哈希和 Release 资产。
13. 窗口图标、托盘图标和底部品牌图标应使用同一套资源。
14. 删除、停用、重置和同步冲突必须使用统一的应用内二次确认窗口。
