# Cherry AI Connect 产品要求

## 功能规则

1. 一个客户端 Key 只能绑定一条中转线路。
2. 客户端 Key 默认名称等于绑定线路名称；用户手动改名后停止自动同步。
3. 思考强度必须完整提供 `low`、`medium`、`high`、`xhigh`、`max` 五档。
4. 客户端 Key 必须支持复制、编辑、停用和删除；删除必须二次确认。
5. 中转线路必须支持新增、编辑、删除、停用、测试连接和刷新模型。
6. 网关重置必须重新随机端口、刷新本地 API 地址、停止旧监听并清理旧运行残留。
7. 使用统计必须同时支持时间范围统计和无时间限制的累计总量。
8. 详细缓存达到 50 MiB 后才清理旧记录，不能清理线路、Key 或累计统计。
9. 设置页必须支持中文/英文切换、检查更新、数据目录和同步状态。
10. 托盘、开机自启、启动隐藏和关闭到托盘必须有明确状态。

## 安全要求

- 上游 Key 只允许进入本地加密存储和内存，不展示完整明文。
- 客户端 Key 不能反推出上游 Key。
- GitHub 只使用用户自己的私有仓库，上传前加密并压缩。
- 默认只需要指定仓库的 `Contents: Read and write` 和自动保留的 `Metadata: Read-only`。
- 不上传 Token、密码、日志中的明文密钥、完整个人路径或未脱敏截图。
- 同步失败时保留本地可用状态，不能用空备份覆盖有效数据。

## 体验要求

按钮名称、图标、颜色和反馈必须表达一致语义：紫色为主要操作，绿色为正常/在线，红色为删除或危险操作。长文本、英文、窄窗口和二次确认窗口不能错位或遮挡。
