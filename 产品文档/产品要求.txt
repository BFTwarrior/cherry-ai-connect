Cherry 多线路网关桌面版产品要求

一、数据与绑定规则
1. 中转站线路字段：线路代号、显示名称、API URL、加密保存的上游 API Key、启用状态、模型目录、最近检测状态、延迟和错误信息。
2. 客户端 Key 字段：名称、Key 摘要、绑定线路、思考强度、创建时间、启用状态。
3. 一个客户端 Key 必须绑定一个有效线路；不能创建没有绑定线路的客户端 Key。
4. 一个客户端 Key 只能绑定一条线路；编辑时也必须保持这个约束。
5. 客户端 Key 要有启用/停用和永久删除两个分开的操作。删除后不能再认证，界面也不能继续保留它。
6. 删除线路前检查是否仍有客户端 Key 绑定；有绑定时给出明确提示，先改绑或删除客户端 Key。
7. 真实上游 Key 不显示在列表、模型目录、普通日志或测试记录中；界面只显示“已配置”和脱敏信息。

二、线路检测与模型
1. 保存线路后可以单独点击“同步模型/检测线路”。
2. 检测请求访问上游线路的 /v1/models，并保存模型列表、时间、耗时和错误信息。
3. 有成功同步记录的旧配置可以迁移为“可用”；没有记录的线路显示“未检测”，不能伪造成功状态。
4. 模型目录按中转站线路分组；支持搜索和按线路筛选；模型名称不能全部挤在一个文本块里。
5. 客户端访问本地 GET /v1/models 时，只返回它所绑定线路的模型。

三、请求转发与思考强度
1. 客户端通过 Authorization: Bearer 本地客户端 Key，或 X-Gateway-Key 访问网关。
2. 网关验证本地 Key 后，删除本地认证头，改用对应线路的真实上游 Bearer Key 请求中转站。
3. Responses 请求写入 reasoning.effort；Chat Completions 请求写入 reasoning_effort。
4. 支持 low、medium、high、xhigh、max 五档。每个客户端 Key 可以单独设置；设置页可以批量应用到已有 Key。
5. “xhigh”或“max”能否被上游实际执行，取决于上游模型和中转站是否支持；网关负责真实透传，不承诺上游一定接受所有档位。

四、桌面交互
1. 总览页要能看到网关状态、线路数、模型数、客户端 Key 数，以及有效客户端 Key 的实际绑定线路；没有有效 Key 时显示明确空状态，不再制造一个无法配置的“默认线路”入口。
2. 线路页要有添加、编辑、同步、检测状态、绑定 Key 数和删除入口。
3. 模型页要按线路展示，使用卡片/网格等清晰布局。
4. 客户端 Key 页要有创建、编辑、启用/停用、删除；新 Key 完整值只在创建完成后展示一次，并提供复制按钮。
5. 设置页要包含默认思考强度、是否应用到现有 Key、开机自启、启动隐藏、关闭进托盘、中英文切换和本地 API 地址复制；不重复提供默认线路选择，线路由每个客户端 Key 的绑定关系决定。
6. 关闭窗口默认隐藏到托盘；真正退出通过托盘菜单完成。
7. 所有危险操作需要明确确认或二次提示，特别是永久删除 Key 和删除线路。

六、网关重置与端口冲突处理
1. 顶部刷新按钮不是单纯刷新页面，而是停止旧 HTTP 监听器并重新启动本地网关。
2. 重置会在 27891-27991 范围内随机选择一个可用端口；127.0.0.1 不变，目的是快速解决与其他本地网关或开发服务的端口冲突。
3. 重置不能删除或重置线路、模型目录、客户端 Key、Key 绑定关系、思考强度和加密上游 Key。
4. 重置完成后所有界面中的端口、API 地址和创建 Key 提示必须同步更新；Cherry 需要重新复制新的 /v1 地址。

五、工程与发布
1. 前端采用 React + TypeScript + Vite，桌面壳采用 Electron。
2. 网关由 Node.js 运行，配置保存为本地 JSON；上游 Key 使用 AES-256-GCM 加密保存。
3. 生产包使用 electron-builder 生成 Windows x64 NSIS 安装程序。
4. 打包前必须通过 TypeScript 检查、Vite 构建和 Node 语法检查。
5. 日志和文档不得记录真实 API Key。

六、0.4.3 客户端凭证与复制要求
1. 客户端 Key 卡片必须提供“复制 Key”和“复制地址”两个高频按钮；按钮应放在卡片首行的脱敏摘要区域，不能和删除、停用等危险操作混在一起。
2. 新版本客户端 Key 必须以本机加密密文保存，卡片只显示脱敏摘要；复制接口只能在本机管理范围内读取对应客户端 Key，不能返回上游 API Key。
3. 历史 Key 没有密文时必须明确提示不可恢复，并提供需要确认的重新生成动作；不能静默生成新值，也不能显示不存在的复制成功。
4. 默认网关监听 127.0.0.1；产品文案必须说明本地 Key 跨电脑不可直接使用，但同机控制风险仍需通过停用、删除或轮换处理。
5. 重置网关的验收必须同时证明：端口改变、旧地址失效、新地址健康、线路/模型/客户端 Key 和最近状态保留。

七、0.4.3 最终验收矩阵
1. 构建：TypeScript、Vite、Electron 主进程、预加载脚本和 gateway 语法检查通过，并生成 Windows x64 NSIS 安装包。
2. 线路：新增、编辑、同步模型、显示成功/失败/未检测、错误摘要和绑定 Key 数量；有绑定时不能直接删除线路。
3. 模型：按线路分组显示，支持全量同步、单线路同步、搜索和失败重试。
4. 客户端 Key：创建时强制选择线路和思考等级；复制、测试、编辑、停用、启用、永久删除均有明确结果。
5. 思考强度：固定五档 low、medium、high、xhigh、max；客户端 Key 独立等级优先于全局默认值；批量覆盖必须二次确认。
6. 桌面：托盘、开机自启、启动隐藏、关闭进托盘、中文/English 和产品图标均有对应设置或状态。
7. 重置：重置期间有过渡态和确认提示；完成后旧地址失效、新地址健康，业务数据保留。
8. 文档：测试记录、问题清单和测试人员说明不得记录任何真实密钥；“待验收”和“待用户验收”必须分开填写。
