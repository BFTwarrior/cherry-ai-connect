Cherry 多线路网关桌面版版本说明

当前版本：1.00 候选版（2026-09-16）
说明：本文件保留各版本变更历史；当前实现和验收结论以《1.00-实现现状与验收报告.txt》为准。

本版本完成：
1. React + TypeScript + Vite 前端重构。
2. Electron Windows 桌面壳与 Node.js 本地网关整合。
3. 多中转站线路管理和上游 /v1/models 同步。
4. 客户端 Key 与中转站线路的一对一绑定关系。
5. 客户端 Key 创建、编辑、启用、停用和永久删除。
6. Responses 与 Chat Completions 的思考强度透传。
7. 中英文界面切换。
8. 开机自启、启动隐藏和关闭进托盘设置。
9. Windows x64 NSIS 安装包。
10. 桌面版内部按 electron、gateway、renderer 和产品文档归类，不再依赖项目外旧网关目录。
11. 【历史 0.4.x】顶部刷新按钮支持停止并重新启动内嵌网关；当前 1.00 端口规则请见文末候选版摘要。
12. 启动和重置时清理已知旧版网关/旧本地代理残留进程。
13. 隐藏页面右侧滚动条但保留鼠标滚轮和触控滚动。
14. 增加产品自有 PNG 托盘图标，更新托盘图标生成方式、应用标识和单击恢复窗口行为。
15. 统一托盘、Windows 窗口/任务栏和 EXE 使用产品自有紫色图标资源，不再使用 Electron 默认图标。
16. 思考强度统一为 low、medium、high、xhigh、max 五档，并真实透传到上游请求。
17. 由于签名工具下载地址在当前网络环境超时，构建配置跳过数字签名；这不影响本地运行、图标显示和功能测试。
18. 修复客户端 Key 与设置页的重复页面标题，避免用户误以为存在两个 Key 或两份设置。
19. 设置页移除与“一客户端 Key 一线路”重复的默认线路选择，线路只在客户端 Key 创建/编辑时绑定。
20. 明确重置网关的产品语义：随机化本地可用端口以解决端口冲突，不随机 IP，不删除任何业务配置。
21. 修复右上角思考等级假按钮：现在可直接选择 low、medium、high、xhigh、max，并明确它是默认值；已有客户端 Key 仍使用自己的绑定等级。
22. 修复设置保存后的界面滞后：默认思考强度保存后，设置页、总览指标和右上角控件使用同一份最新状态。
23. 修复客户端 Key 复制闭环：增加复制成功 Toast、失败提示、Windows 备用复制方式和手动选中复制方案。
24. 修复线路异常反馈：线路卡片展示可读错误摘要和可复制详情；线路恢复后清除旧错误。
25. 修复总览完成度判断：第四步必须检测到真实客户端请求成功，不能仅凭存在启用 Key 判定完成；前端自动读取状态，不需要手动刷新页面。
26. 修复 Windows 快捷键提示：Windows 显示 Ctrl+1 至 Ctrl+4 并支持实际导航，macOS 显示 Command 快捷键。
27. 修复网关重置过渡态：重置期间显示重启中并禁用相关控件，管理数据加载完成后才恢复在线。
28. 清理侧栏重复的数据目录入口，并降低总览、线路和设置卡片的无效留白。

0.4.2 修复与验收基线：
29. 最近一次客户端请求的时间、状态和模型写入本地配置；重启后总览不会把已成功的真实请求误判为从未测试。
30. 网关停止时主动清理活动 HTTP socket 和 Keep-Alive 连接，修复重置网关偶发卡在“重启中”的问题。
31. 总览统计卡改为只读，欢迎区和 QUICK START 每个入口只负责一个明确动作，减少重复入口和误操作。
32. QUICK START 的模型同步直接执行批量同步；模型页增加进度、失败线路和“重试失败线路”。
33. 总览路由摘要改为展示当前有效客户端 Key 的真实绑定线路和思考等级，不再显示无法设置的默认中转站。
34. 设置页改为即时生效；“应用到已有 Key”是独立的、有明确影响范围的动作。
35. 顶部本地 API 地址可以直接复制；客户端 Key 卡片增加“测试连接”，并写入最近一次客户端测试状态。
36. 普通刷新图标改为明确的“重置网关”按钮；点击前说明旧地址失效、端口随机变化、业务数据保留。
37. 完成 0.4.2 Windows x64 构建、五档思考等级、Key 生命周期、异常线路、持久化和活动连接回归；最终安装包为 `dist\Cherry-多线路网关-0.4.2.exe`。

已知改进项：
1. 不同上游线路对思考强度的支持不一致，正式发布前可增加线路级能力探测。
2. 后续可以把配置存储从 JSON 迁移到 SQLite，但这不是本版本的必要条件。

0.4.3 增量功能：
38. 客户端 Key 卡片增加“复制 Key”和“复制地址”快捷按钮；新版本客户端 Key 的密文保存在本机，列表页可安全重复复制，不再要求用户重新打开创建结果窗口。
39. 增加本地客户端 Key 密文读取接口和旧版 Key 兼容提示；没有历史密文的旧 Key 不会假装可恢复，只能在确认后重新生成，旧 Key 立即失效。
40. 明确安全边界：中转站 Key 始终留在网关本机并加密保存；客户端 Key 只对本机 127.0.0.1 网关有意义，不包含真实上游凭证。
41. 0.4.3 最终 Windows x64 安装包为 `dist\Cherry-多线路网关-0.4.3.exe`；已完成复制按钮、临时 Key 生命周期和重置随机端口回归。

0.4.3 文档收口说明：
42. 新增 `产品文档\00-交付总览与文档索引.txt`，统一说明文档优先级、代码链路、按钮语义、测试顺序、安全边界和状态标签。
43. “待修复”“待验收”“待用户验收”现在按不同含义记录；历史章节保留追溯信息，最终状态以交付总览、问题清单最新章节和测试人员说明末尾摘要为准。
44. UI-025 低高度窗口下侧栏版本信息贴边/裁切仍明确保留为待修复；本次只完成文档收口，没有把它伪装成已修复。
45. 文档再次明确 0.4.3 使用 JSON 配置，不依赖 SQLite；运行数据路径以“设置 > 打开数据目录”为准。

0.4.3 最终开发修复补充：
46. 修复低高度窗口下渲染层强制最小高度导致的侧栏底部版本信息裁切；由 Electron 窗口负责最小尺寸，侧栏状态卡和版本行在视口内保持完整。
47. 收紧总览欢迎区和右侧轨道装饰，减少首屏无操作装饰占用，保留本地网关状态和产品识别。
48. 本次修复通过 TypeScript、前端构建、Electron/gateway 语法检查、Windows x64 打包和隔离接口回归；UI-025 转为“待验收”，不改变 UI-001 至 UI-024 及托盘/Cherry Studio 的“待用户验收”标签。

0.4.4 增量功能：
49. 客户端 Key 默认名改为绑定线路名；未自定义时跟随线路改名，用户手动改名后不再自动覆盖。
50. 增加本地使用统计页，支持 24 小时、7 天、30 天、90 天和半年，支持线路、模型和状态筛选。
51. 同时采集流式和非流式上游响应的 Token、缓存读写、请求状态、耗时和 TTFT；不记录提问、回答或密钥。
52. 新增没有时间限制的永久累计总账。半年外明细可清理，但累计请求和累计 Token 不得减少或归零。
53. 设置页增加 GitHub Release 手动检查更新；不静默下载、不自动安装。
54. 新增 `npm test` 隔离端到端回归，覆盖自动命名、自定义锁定、流式/非流式用量和永久总账不随明细剪枝。
55. 检查更新增加 GitHub Release 官方跳转备用通道；匿名 API 被限流时仍可读取最新标签。

1.00 候选版（2026-09-16，覆盖旧版当前规则）：
56. 产品正式更名为“Cherry AI 连接中心 / Cherry AI Connect”；普通用户界面减少“网关”术语，代码和历史兼容名称保留。
57. 使用 SQLite 保存请求明细、永久总账、设备计数器、同步队列和同步运行记录。
58. 明细规则改为 50 MiB 上限、约 45 MiB 回落；“最新 200 条”只是单页展示量，不再按半年或 50,000 条删除，永久累计没有时间限制。
59. 随机端口扩展为 20000-48999 共 29,000 个候选端口，使用系统安全随机数，跳过当前端口和已占用端口。
60. 正式包运行数据统一到“EXE 所在目录\data”；安装到 D 盘时缓存和主要数据也跟随到 D 盘。删除软件目录前必须先同步或备份 data。
61. 增加 GitHub 私有 Release 加密同步：不可变分片、manifest 最后提交、下载校验、G-Counter、冲突选择、错误密码保护、恢复码、孤儿清理和资产数量保护。
62. 当前 GitHub 连接方式为用户创建的 PAT，并由 Windows 安全存储保护；OAuth Device Flow 尚未实现。
63. 新增打包前 clean-dist 防护，避免解包运行产生的缓存、线路、Key 或测试配置进入安装包。
64. 20 项自动测试、生产依赖漏洞扫描、敏感凭证格式扫描、浏览器视觉验收和解包版 version=1.00 冒烟已通过。
65. 当前安装包 `dist\Cherry-AI-Connect-Setup-1.00.exe` 是候选版；真实 GitHub、Cherry Studio、NSIS 安装/卸载、托盘和开机启动未全部验收前不得称为正式发布完成。
66. 当前唯一实现现状和验收结论以 `产品文档\1.00-实现现状与验收报告.txt` 为准。
