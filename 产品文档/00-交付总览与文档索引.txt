一、交付结论先看
======================================================================

当前交付对象是一个运行在 Windows 本机的 Electron 桌面网关。它把 Cherry Studio 或其他 OpenAI 兼容客户端的请求接到本机 127.0.0.1 网关，再按照客户端 Key 绑定的线路转发到对应中转站。

核心规则只有三条：
1. 一个客户端 Key 必须绑定一条且只能绑定一条中转站线路。
2. 中转站 URL 和真实上游 API Key 只保存在网关本机；客户端只使用本地生成的客户端 Key。
3. “重置网关”只随机更换本地端口，用于处理端口冲突；不会删除线路、模型、客户端 Key、绑定关系或思考强度。

当前版本的五档思考强度为：
low、medium、high、xhigh、max。

当前仍需保留的边界：
1. UI-025“低高度窗口下侧栏版本信息贴边/裁切”已完成代码修复和开发侧回归，当前为“待验收”，等待测试人员在最低支持窗口高度下现场确认。
2. 标记为“待用户验收”的托盘、Cherry Studio 完整对话和最终视觉体验，不由开发文档代替用户确认。
3. 上游是否接受 xhigh 或 max 取决于中转站、模型权限和网络线路；网关负责透传，不承诺所有上游都支持。

四、代码和请求链路
======================================================================

1. Electron 启动时读取桌面设置，选择 127.0.0.1 的可用端口，启动内嵌 gateway，并创建窗口和托盘。
2. React 页面通过本机管理接口读取线路摘要、模型数量、客户端 Key 摘要、设置和最近请求状态。
3. 添加线路时，URL 和上游 Key 写入本机配置；前端列表只显示名称、地址、状态、模型数、延迟和脱敏信息。
4. 创建客户端 Key 时，后端生成 cg_ 开头的随机值，保存哈希用于认证，并保存加密密文用于用户主动复制；列表只返回摘要和 hasSecret 状态。
5. Cherry 请求携带本地客户端 Key。网关先验证本地 Key，再根据 providerId 找到唯一绑定线路，解密上游 Key，并替换鉴权头转发。
6. 客户端访问 /v1/models 时，只返回该客户端 Key 绑定线路的模型；客户端 Key 不会看到其他线路的模型或上游 Key。
7. Responses 请求使用 reasoning.effort；Chat Completions 请求使用 reasoning_effort。客户端 Key 的独立等级优先于全局默认等级。
8. 网关只监听 127.0.0.1。即使别人拿到本地客户端 Key，也不能在另一台电脑上直接访问这台电脑的回环地址；但同一台电脑被控制时仍需立即停用、删除或重新生成凭证。

五、界面和按钮的最终语义
======================================================================

总览：
- 网关状态：只显示本机网关是否在线、当前端口和最近一次客户端请求结果。
- 四步配置：添加线路、同步模型、创建客户端 Key、完成一次真实客户端请求。
- 统计卡：只读，不再把数字卡片伪装成多个重复操作入口。
- 路由摘要：显示有效客户端 Key 实际绑定的线路和思考等级；没有配置时显示明确空状态。

中转站线路：
- 添加线路：填写线路代号、名称、API URL、上游 Key；保存后可同步模型。
- 编辑：修改线路资料；如果有 Key 绑定，不允许把绑定关系变成空值。
- 同步/检测：访问该线路的 /v1/models，保存模型、状态、延迟、时间和错误摘要。
- 删除：有客户端 Key 绑定时必须先改绑或删除 Key；确认后才永久删除线路。
- 线路页不承担模型目录的重复同步入口；统一同步入口在模型目录页。

模型目录：
- 同步全部：按线路逐一同步，并显示进度和失败线路。
- 线路分组同步：只同步当前线路。
- 搜索/筛选：只影响显示，不改变本地模型数据。
- 模型以线路分组和小卡片展示，不能把多条线路的模型堆成一段文字。

客户端 Key：
- 生成客户端 Key：必须选择一条线路和一个思考等级；成功后展示一次完整值。
- 复制 Key：只对有本机密文的新版本 Key 提供，复制的是本地客户端 Key，不是上游 Key。
- 复制地址：复制当前实时的 http://127.0.0.1:端口/v1；重置后自动使用新端口。
- 测试连接：使用该 Key 访问本机 /v1/models，并记录最近客户端测试结果。
- 编辑：修改名称、绑定线路或思考等级；仍保持一 Key 一线路。
- 停用/启用：停用立即阻止认证，但保留记录；启用恢复认证。
- 删除：永久删除本地客户端 Key；删除后旧 Key 必须认证失败，不能只从界面隐藏。
- 旧版无密文 Key：不显示虚假的复制 Key 入口；只能在确认后重新生成，旧值立即失效。

设置：
- 默认思考：全局默认值；已有 Key 不会自动改变。
- 应用到已有 Key：单独的批量覆盖动作，必须显示影响数量并二次确认。
- 开机自启：使用 Windows 登录启动设置。
- 启动后隐藏：启动后不显示主窗口，网关和托盘继续运行。
- 关闭进托盘：点窗口关闭按钮时隐藏到托盘；通过托盘“退出”才真正结束进程。
- 界面语言：中文/English 即时切换，不改变业务数据。
- 本地 API 地址：显示当前 /v1 地址并提供复制；重置后更新。
- 打开数据目录：打开实际运行数据目录，不把密文内容显示在页面上。

重置网关：
- 不是普通页面刷新，而是停止旧监听、清理活动连接、随机选择 27891-27991 范围内的可用端口、重新启动并重新加载数据。
- 确认窗口必须写明旧地址失效、端口随机变化、线路/模型/Key 保留。
- 重置期间显示“网关重启中”，禁用重复重置和依赖当前地址的操作；新管理数据加载完成后才恢复在线。

十一、1.00 正式版最终实施基线（2026-09-16）
======================================================================

1.00 的唯一最终技术方案和执行顺序，请阅读《1.00-最终实施方案（架构审计收敛版）.txt》。该文件已经核对 5.6-sol 提供的 71 页架构审计提示，并明确区分了“1.00 必须完成”“推荐后置”和“明确不做”。

1.00 相比 0.4.4 的关键架构变化：
- config.json 继续保存普通界面和线路显示配置，避免无必要地推翻现有结构。
- usage.db 使用 SQLite WAL 保存使用明细、永久总账、待同步队列、删除墓碑和同步记录；正式 EXE 自带组件，用户不需要另装 SQLite。
- GitHub 使用一个私有仓库和一个固定 Release Asset；采用不可变 generation、manifest 最后提交、三代回滚和孤儿资产宽限清理。
- 使用 eventId 去重、deviceId + deviceEpoch 的 G-Counter 和配置冲突预览，防止多设备重复统计或静默覆盖。
- 中转站 API URL、认证方式、代理、TLS 和上游 Key 一起进入加密 vault；客户端 Key 完整值仍只留在本机。
- 默认每 30 分钟同步一次；启动、退出、开启、关闭、手动同步、恢复、账户变更、密码变更和安全连接配置变更触发一次同步尝试。
