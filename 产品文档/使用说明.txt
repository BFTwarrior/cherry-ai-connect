Cherry 多线路网关桌面版使用说明

一、启动
1. 安装 `Cherry-多线路网关-0.4.3.exe`；如果使用其他版本，以安装包文件名和界面左下角版本号为准。
2. 启动后，网关首次通常监听 http://127.0.0.1:27891；如果端口被占用，程序会在 27891-27991 中选择可用端口。关闭窗口默认进入系统托盘。
3. 需要完全退出时，在系统托盘右键选择退出；只关窗口不会停止网关。

二、添加中转站线路
1. 打开“中转站线路”，点击“添加线路”。
2. 填写线路代号、显示名称、API URL 和上游 API Key。
3. 保存后点击“同步模型/检测线路”。成功后会显示模型数量、检测时间和延迟。
4. 如果检测失败，先检查 URL 是否为 OpenAI 兼容地址、Key 是否有效，以及 Clash/VPN 是否能访问该域名。

三、创建客户端 Key
1. 打开“客户端 Key”，点击“生成客户端 Key”。
2. 填写名称，选择唯一绑定的中转站线路和思考强度。
3. 创建成功后立即复制完整 Key。完整值只在这次创建结果中展示，关闭弹窗后列表只显示脱敏摘要。
4. 在 Cherry Studio 中填写：
   API 地址：设置页显示的当前本地 API 地址（通常形如 http://127.0.0.1:27891/v1）
   API Key：刚创建的客户端 Key
   模型：模型目录中的名称

四、思考强度
1. 可选 low、medium、high、xhigh、max。
2. 顶部“默认思考”下拉框可以直接修改全局默认值；设置页也可以修改并选择是否同时应用到已有客户端 Key。
3. 设置会随本地网关请求转发到上游；Responses 使用 reasoning.effort，Chat Completions 使用 reasoning_effort。客户端 Key 自己保存的等级优先于全局默认值。
4. 如果上游不支持某一档，检测或聊天可能返回上游错误，此时改用它支持的档位。

五、Key 管理
1. “停用”会保留记录但立即禁止使用，适合临时暂停。
2. “启用”恢复使用。
3. “删除”是永久删除本地客户端 Key，之后 Cherry 使用它会返回无效 Key；需要确认后再操作。
4. 删除中转站线路前，需要先改绑或删除所有绑定它的客户端 Key。

六、设置与备份
1. 设置页可以修改默认思考强度、现有 Key 批量应用、语言和托盘行为。线路在客户端 Key 创建/编辑时绑定，不在设置页重复选择。
2. 开机自启和启动后隐藏可以按需打开；首次排障时建议关闭“启动后隐藏”，方便观察界面。
3. 配置数据保存在应用数据目录中。迁移电脑前，请在设置页打开数据目录并备份配置文件与网关密钥文件；不要把包含密文配置的文件公开上传。

七、排障顺序
1. 先看网关状态是否为运行中。
2. 再检测中转站线路和同步模型。
3. 如果线路显示异常，先阅读线路卡片上的错误摘要；需要发给测试人员时点击“复制详情”。
4. 再确认客户端 Key 绑定的是正确线路且没有停用。
5. 最后在 Cherry 中检查 API 地址、Key 和模型；网络代理只影响需要访问上游的请求，不影响本地界面本身。

八、网关异常时的重置
1. 点击窗口顶部的“重置网关”按钮，不要把它当作普通页面刷新。
2. 该按钮会关闭当前内嵌网关、清理已知旧版网关残留进程，并在 27891-27991 中随机选择新端口重新启动本地网关。
3. 线路、模型、客户端 Key、绑定关系和思考强度不会被删除。
4. 127.0.0.1 不变，但端口可能变化；从设置页复制新 API 地址到 Cherry，再发送测试消息。
5. 重置的目的是快速避开与其他本地网关的端口冲突，不是更换中转站线路。

十一、给测试人员的最短执行路径
1. 先从“设置”复制当前本地 API 地址，再确认网关状态为在线。
2. 在线路页使用测试线路同步模型，确认模型目录按线路分组显示。
3. 在客户端 Key 页生成临时 Key，复制 Key 和地址，完成一次测试连接。
4. 在 Cherry Studio 中填入“当前 /v1 地址 + 本地客户端 Key + 已同步模型”，发送一句最短测试消息。
5. 依次测试停用、启用和删除临时 Key；不要用唯一正式 Key 做删除测试。
6. 最后重置网关，记录旧端口和新端口；把新地址重新复制到 Cherry Studio。
7. 测试结束清理临时线路和临时 Key，并在报告中只保留端口、模型数、状态码和脱敏名称。

十二、数据备份和迁移注意事项
1. 通过“设置 > 打开数据目录”确认实际运行数据位置；不要凭猜测去复制源码目录。
2. 迁移前同时备份 config.json 和 .gateway-secret，缺少后者可能导致已保存的上游密文无法解密。
3. 备份文件只能放在受信任位置；不要提交到 GitHub、聊天、截图或测试报告。
4. 迁移到另一台电脑后，原机的本地客户端 Key 不会自动变成远程 Key；需要在新机重新配置并重新生成测试凭证。

九、托盘图标
1. 正常运行时，Windows 任务栏右侧通知区域应显示 Cherry 紫色图标。
2. 如果图标进入隐藏区域，点击通知区域的上箭头查看，并在 Windows 任务栏设置中允许 Cherry Gateway 显示。
3. 单击图标恢复窗口，右键图标可以显示、隐藏、设置开机启动或退出。

安全提醒：不要把上游 API Key 发给别人，也不要把它粘贴到截图、聊天记录或公开仓库中。

十、客户端 Key 卡片的快速复制与保密
1. 打开“客户端 Key”，每张卡片右上方都有“复制 Key”和“复制地址”。“复制 Key”复制的是给 Cherry 使用的本地客户端 Key；“复制地址”复制的是当前实时的 `http://127.0.0.1:端口/v1`。
2. 复制成功后右下角会显示 Toast。网关重置期间复制地址按钮会暂时禁用，重置完成后自动对应新端口。
3. 新版本客户端 Key 会以加密密文保存在本机，因此卡片可以再次复制；完整值不会显示在卡片文字、普通日志或测试文档中。
4. 旧版 Key 如果没有本地密文，点击复制会提示无法恢复，并显示“重新生成”。确认重新生成后，旧 Key 立即失效，需要把新 Key 重新填入 Cherry。
5. 中转站线路里的真实 API Key 仍只由网关使用，客户端 Key 不等于中转站 Key。别人拿到本地 Key，不能在另一台电脑上直接使用，因为网关默认只监听本机 `127.0.0.1`；但同一台电脑被他人控制时仍应立即停用、删除或重新生成 Key。
